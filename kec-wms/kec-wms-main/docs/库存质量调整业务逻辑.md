# 库存质量调整业务逻辑

## 概述

库存质量调整是 WMS 系统中的重要功能，用于调整库存的质量状态（如从良品调整为次品，或从次品调整为良品）。该功能确保不同质量状态的商品只能存放到相应质量类型的库区，防止质量混淆。

## 核心概念

### 库存桶类型（Bucket Type）

库存桶类型表示库存的状态和质量：

- **AVAILABLE**：可用库存（良品，可正常销售）
- **ALLOCATED**：已分配库存（良品，已锁定给订单）
- **PICKING**：拣货中库存（良品，正在拣货）
- **FROZEN**：冻结库存（良品，暂时不可用）
- **DEFECTIVE**：不良品库存（次品/破损，不可正常销售）
- **QC_HOLD**：质检暂扣库存（质量待定）
- **COUNT_HOLD**：盘点暂扣库存（盘点中）

### 库区质量类型（Zone Quality Type）

库区质量类型定义了库区可以存放的商品质量：

- **GOOD**：良品区（只能存放良品）
- **DEFECTIVE**：次品区（只能存放次品）
- **DAMAGED**：损坏区（只能存放损坏品）

### 质量映射规则

系统定义了 Bucket Type 到 Zone Quality Type 的映射关系：

| Bucket Type | 允许的 Zone Quality Type | 说明 |
|------------|------------------------|------|
| AVAILABLE | GOOD | 可用库存只能放良品区 |
| ALLOCATED | GOOD | 已分配库存只能放良品区 |
| PICKING | GOOD | 拣货中库存只能放良品区 |
| FROZEN | GOOD | 冻结库存只能放良品区（冻结是状态，不是质量问题） |
| DEFECTIVE | DEFECTIVE, DAMAGED | 不良品可以放次品区或损坏区 |
| QC_HOLD | GOOD | 质检暂扣可以放良品区（质量待定） |
| COUNT_HOLD | GOOD | 盘点暂扣可以放良品区（盘点是流程，不是质量问题） |

## 业务规则

### 1. 质量类型限制

**规则**：调整后的库位必须符合目标质量类型的要求

- 良品（AVAILABLE、FROZEN 等）只能放到良品区（GOOD）
- 次品/破损品（DEFECTIVE）只能放到次品区（DEFECTIVE）或损坏区（DAMAGED）

**示例**：
- ✅ 允许：将 AVAILABLE 库存调整到 GOOD 库区的库位
- ❌ 禁止：将 DEFECTIVE 库存调整到 GOOD 库区的库位
- ✅ 允许：将 DEFECTIVE 库存调整到 DEFECTIVE 库区的库位

### 2. 质量调整流程

1. **选择库存**：选择需要调整质量的库存项
2. **选择目标质量类型**：选择调整后的 Bucket Type
3. **选择目标库位**：系统自动过滤出符合目标质量类型的库位
4. **填写调整原因**：必填，用于审计追溯
5. **执行调整**：系统验证并执行质量调整

### 3. 库位过滤机制

当用户选择目标质量类型后，系统会自动过滤库位列表：

```typescript
// 前端调用 API 时传入目标质量类型
GET /api/v1/bin-locations?warehouseId={id}&targetBucketType=DEFECTIVE

// 后端根据质量映射规则过滤库位
// 只返回库区质量类型为 DEFECTIVE 或 DAMAGED 的库位
```

### 4. 执行时验证

在执行质量调整时，系统会进行二次验证：

1. 查询目标库位的库区信息
2. 检查库区质量类型是否符合目标 Bucket Type
3. 如果不符合，抛出错误并回滚事务

```typescript
// 验证逻辑
const isQualityMatch = canStoreBucketInZone(
  toBucketType,      // 目标 Bucket Type
  zone.qualityType   // 库区质量类型
)

if (!isQualityMatch) {
  throw new Error('质量类型不匹配')
}
```

## 调整流程

### 1. 创建调整单

```typescript
POST /api/v1/inventory/adjustments

{
  "warehouseId": "warehouse-uuid",
  "adjustmentType": "QUALITY_ADJUST",
  "reason": "商品破损",
  "lines": [{
    "skuId": "sku-uuid",
    "locationId": "source-location-uuid",
    "fromBucketType": "AVAILABLE",
    "toBucketType": "DEFECTIVE",
    "toLocationId": "target-location-uuid",
    "toLocationCode": "DEFECT-A-01-01",
    "batchNumber": "BATCH001",
    "lpn": "LPN001",
    "adjustQuantity": 10,
    "reason": "商品破损"
  }]
}
```

### 2. 执行调整

```typescript
POST /api/v1/inventory/adjustments/{id}/execute
```

**执行步骤**：

1. **验证目标库位**：
   - 查询目标库位的库区信息
   - 验证库区质量类型是否符合目标 Bucket Type

2. **减少源库存**：
   - 从源库位的源 Bucket Type 减少库存
   - 创建 OUT 事件记录

3. **增加目标库存**：
   - 向目标库位的目标 Bucket Type 增加库存
   - 创建 IN 事件记录

4. **更新调整单状态**：
   - 将调整单状态更新为 EXECUTED
   - 记录执行时间和执行人

### 3. 事务保证

所有操作在一个数据库事务中完成，确保数据一致性：

```typescript
await prisma.$transaction(async (tx) => {
  // 1. 验证目标库位
  const targetLocation = await tx.binLocation.findUnique({
    where: { id: targetLocationId },
    include: { zone: true }
  })

  // 2. 验证质量类型匹配
  if (!canStoreBucketInZone(toBucketType, targetLocation.zone.qualityType)) {
    throw new Error('质量类型不匹配')
  }

  // 3. 减少源库存
  await adjust({ quantityDelta: -quantity, bucketType: fromBucketType }, tx)

  // 4. 增加目标库存
  await adjust({ quantityDelta: +quantity, bucketType: toBucketType }, tx)

  // 5. 更新调整单
  await tx.inventoryAdjustment.update({
    where: { id },
    data: { status: 'EXECUTED' }
  })
})
```

### 获取库位列表（支持质量过滤）

```
GET /api/v1/bin-locations?warehouseId={id}&targetBucketType={type}
```

**参数**：
- `warehouseId`：仓库 ID（必填）
- `targetBucketType`：目标 Bucket Type（可选，用于质量过滤）

**响应**：
```json
{
  "success": true,
  "data": [
    {
      "id": "location-uuid",
      "locationCode": "A-01-01-01",
      "zone": {
        "id": "zone-uuid",
        "zoneCode": "GOOD-A",
        "zoneName": "良品区A",
        "qualityType": "GOOD"
      }
    }
  ]
}
```

```
POST /api/v1/inventory/adjustments
```

**请求体**：

## 数据模型

### Zone（库区表）

```prisma
model Zone {
  id           String   @id @default(uuid())
  zoneCode     String   // 库区编码
  zoneName     String?  // 库区名称
  zoneType     String   // 库区类型
  qualityType  String   @default("GOOD")  // 质量类型：GOOD, DEFECTIVE, DAMAGED
  // ...
}
```

### BinLocation（库位表）

```prisma
model BinLocation {
  id           String   @id @default(uuid())
  locationCode String   // 库位编码
  zoneId       String   // 所属库区
  zone         Zone     @relation(fields: [zoneId], references: [id])
  // ...
}
```

### InventoryAdjustment（库存调整单表）

```prisma
model InventoryAdjustment {
  id              String   @id @default(uuid())
  adjustmentType  String   // 调整类型：QUALITY_ADJUST
  status          String   // 状态：DRAFT, EXECUTED
  lines           InventoryAdjustmentLine[]
  // ...
}
```

### InventoryAdjustmentLine（调整单明细表）

```prisma
model InventoryAdjustmentLine {
  id              String   @id @default(uuid())
  fromBucketType  String?  // 调整前桶类型
  toBucketType    String?  // 调整后桶类型
  fromLocationId  String?  // 调整前库位
  toLocationId    String?  // 调整后库位
  quantityChange  Int      // 调整数量
  // ...
}
```

## 常见问题

### Q1: 为什么要限制质量类型和库区的匹配？

**A**: 这是为了防止质量混淆：
- 良品和次品必须物理隔离，避免误发货
- 便于库存管理和盘点
- 符合仓储管理的最佳实践

### Q2: 如果库区质量类型设置错误怎么办？

**A**: 需要先修改库区的质量类型，然后才能进行质量调整。系统会在执行时验证，确保数据一致性。

### Q3: 质量调整是否支持跨库位？

**A**: 支持。质量调整可以同时变更质量类型和库位，但目标库位必须符合目标质量类型的要求。

### Q4: 质量调整是否可以撤销？

**A**: 可以通过创建反向的质量调整单来撤销。例如，如果误将 AVAILABLE 调整为 DEFECTIVE，可以再创建一个从 DEFECTIVE 调整回 AVAILABLE 的调整单。

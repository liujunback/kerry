# 范围生成锁定与批次拆分

## 1. 覆盖入口

后端入口：

- `POST /api/v1/inventory/counts`
- `POST /api/v1/inventory/counts/[id]/generate`
- `backend/src/lib/services/inventory-count/service.ts`
- `backend/src/lib/services/inventory-count/scope-generation.ts`

## 2. 创建盘点单

创建接口会根据 `saveMode`（保存模式）决定初始状态：

- `DRAFT`：只保存草稿，不生成范围
- `PENDING_SCOPE`：等待生成范围

创建时会保存：

- 盘点类型
- 盘点方式
- 仓库
- 计划时间
- 货主范围
- 盘点范围配置
- 执行配置

创建阶段不直接生成明细，也不会锁库存。

## 3. 范围来源

范围生成从 `inventory_bucket`（库存桶）读取当前库存事实，按盘点类型和范围配置过滤：

- 全仓盘点按库存状态、货主范围等过滤
- 库位盘点按库区、巷道、货架、库位范围过滤
- SKU（商品）盘点按 SKU（商品）编码范围过滤
- 循环盘点有校验入口，但当前创建页已经隐藏循环盘点选项

范围生成前会检查目标范围内是否存在脏的盘点差异桶，避免旧盘点遗留的 `COUNT_SURPLUS`（盘盈桶）或 `COUNT_SHORTAGE`（盘亏桶）影响新盘点。

## 4. 库存锁定

范围生成会把纳入盘点范围的库存从原库存桶移动到盘点锁定桶：

- 原库存桶减少数量
- `COUNT_HOLD`（盘点锁定桶）增加数量
- 创建 `inventory_count_lock`（盘点锁）记录原始来源

这样做的目标是避免盘点期间该批库存继续被正常出库、调整或转移消耗。

## 5. 明细和批次

范围生成会创建：

- `inventory_count_detail`：每个库存事实维度一条
- `inventory_count_batch`：按执行规则拆分出的任务批次
- `inventory_count_round_line`：每条明细在对应批次里的初盘轮次行

当前拆批规则以 `BY_LOCATION`（按库位）为主，并会结合库位优先级、库位顺序、库位编码排序，保证 PDA（手持端）执行顺序稳定。

## 6. 状态变化

生成前后主要状态变化：

1. `PENDING_SCOPE` 或可重新生成的状态进入生成流程。
2. 生成时清理旧的生成范围和孤儿锁。
3. 生成成功后盘点单进入 `READY`。
4. 批次初始为 `READY`。
5. 明细初始为 `PENDING`。
6. 轮次行初始为 `PENDING`。

如果生成失败，盘点单会进入 `SCOPE_FAILED`。

## 7. 取消盘点

取消盘点时，当前代码只允许部分状态取消，例如 `DRAFT`、`PENDING_SCOPE`、`READY`。取消会释放仍处于 active（有效）的盘点锁，把盘点锁定桶数量归还到来源库存桶，并把盘点单状态更新为 `CANCELLED`。

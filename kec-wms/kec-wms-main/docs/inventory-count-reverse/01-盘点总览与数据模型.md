# 盘点总览与数据模型

## 1. 覆盖范围

当前盘点模块的核心表是：

- `inventory_count_order`
- `inventory_count_batch`
- `inventory_count_detail`
- `inventory_count_round_line`
- `inventory_count_disposal`
- `inventory_count_lock`
- `inventory_adjustment`

## 2. 盘点单

`InventoryCountOrder`（盘点单）是计划和汇总层，关键字段包括：

- `orderNumber`：盘点单号
- `orderName`：盘点单名称
- `orderType`：`FULL`、`LOCATION`、`SKU`、`CYCLE`
- `countMode`：`BLIND` 或 `OPEN`
- `status`：`DRAFT`、`PENDING_SCOPE`、`GENERATING_SCOPE`、`SCOPE_FAILED`、`READY`、`IN_PROGRESS`、`PENDING_ADJUST`、`COMPLETED`、`CANCELLED`
- `warehouseId`、`warehouseName`
- `ownerScopeConfigJson`：货主范围
- `scopeConfigJson`：盘点范围
- `executionConfigJson`：执行规则，例如拆批规则和 PDA（手持端）模式
- `totalBatchCount`、`completedBatchCount`、`totalDetailCount`、`diffDetailCount`、`pendingRecountCount`、`pendingAdjustCount`

订单层不直接保存盘点人和复盘人。当前默认执行人信息主要在 `executionConfigJson`（执行配置）和批次层字段中体现。

## 3. 批次

`InventoryCountBatch`（盘点批次）是执行任务层：

- `batchType`：`FIRST` 或 `RECOUNT`
- `status`：`READY`、`IN_PROGRESS`、`PENDING_RECOUNT`、`RECOUNTING`、`COMPLETED`、`CANCELLED`
- `scopeSummary` 和 `scopeSnapshotJson`：批次范围摘要和快照
- `counterUserId/counterUserName`：初盘人
- `reviewerUserId/reviewerUserName`：复盘人

PDA（手持端）列表和详情实际围绕批次展开。

## 4. 明细

`InventoryCountDetail`（盘点明细）是库存事实维度：

- 客户、仓库、库区、库位、SKU（商品）
- 批次号、LPN（容器号）、库存桶类型、效期、生产日期
- `bookQuantity`：账面数量
- `finalQuantity`：最终实盘数量
- `diffQuantity`：差异数量
- `status`：`PENDING`、`FIRST_COUNTED`、`RECOUNT_PENDING`、`RECOUNTED`、`CONFIRMED`、`ADJUST_CREATED`、`ADJUSTED`、`CANCELLED`
- `adjustmentId`：关联库存调整单
- `disposalId`：关联差异处理单

明细唯一性按 `orderId + clientId + locationId + skuId + batchNumber + lpn + bucketType + expiryDate` 收敛。

## 5. 轮次行

`InventoryCountRoundLine`（盘点轮次行）承载初盘和复盘提交记录：

- `roundType`：`FIRST` 或 `RECOUNT`
- `roundNo`：轮次序号
- `status`：`PENDING`、`SUBMITTED`、`RECOUNT_REQUIRED`、`CONFIRMED`、`CANCELLED`
- `bookQuantitySnapshot`：账面数量快照
- `countedQuantity`：实盘数量
- `diffQuantity`：差异数量
- `counterUserId/counterUserName`：实际提交人
- `countedAt`：盘点时间

同一个明细可以有初盘轮次行和复盘轮次行，因此排查提交结果时不能只看 `inventory_count_detail`。

## 6. 差异处理单

`InventoryCountDisposal`（盘点差异处理单）用于差异后的后续处理，状态为：

- `PENDING`
- `PROCESSING`
- `DONE`
- `CANCELLED`

结算前如果还存在未完成差异处理单，当前代码会阻止盘点单结算。

# 策略配置版本与发布

## 1. 覆盖入口

后端入口：

- `GET /api/v1/wave-strategies`
- `POST /api/v1/wave-strategies`
- `GET /api/v1/wave-strategies/[id]`
- `PUT /api/v1/wave-strategies/[id]`
- `POST /api/v1/wave-strategies/[id]/publish`
- `POST /api/v1/wave-strategies/[id]/copy`
- `POST /api/v1/wave-strategies/[id]/rollback`
- `POST /api/v1/wave-strategies/[id]/simulate`
- `POST /api/v1/wave-strategies/[id]/execute`

## 2. 核心表

波次策略表族：

- `wave_strategy`：策略主表，保存仓库、编码、名称、状态、优先级、当前版本
- `wave_strategy_version`：策略版本，保存版本号、发布状态、快照
- `wave_strategy_rule_set`：规则集，保存触发、筛选、执行、波次类型、拣货、释放配置
- `wave_strategy_run`：运行主记录
- `wave_strategy_run_order`：运行订单明细

波次执行后还会写：

- `wave`
- `wave_order`
- `outbound_order`
- `outbound_order_wave_context`

## 3. 规则结构

`waveStrategyRuleSetSchema`（波次策略规则校验）当前包含：

- `triggerConfig`：触发方式，支持 `MANUAL`、`SCHEDULED`、`API`
- `filterConfig`：订单筛选条件
- `executionConfig`：执行批次、排序、每次最大订单数
- `waveTypeConfig`：六类波次类型配置
- `pickConfig`：拣货拆分配置
- `releaseConfig`：释放方式，`IMMEDIATE` 或 `MANUAL`

## 4. 创建策略

创建策略会在事务中写：

1. `wave_strategy`
2. 第一个 `wave_strategy_version`，状态为 `EDITING`
3. `wave_strategy_rule_set`
4. 回写 `currentVersionId`

同一租户内策略编码不能重复。

## 5. 更新策略

更新策略会确保存在可编辑版本，然后更新：

- 策略编码、名称、描述、优先级、状态
- 当前编辑版本快照
- 当前规则集 JSON（数据交换格式）

如果状态发生变化，会同步定时任务。

## 6. 发布策略

发布策略会：

1. 校验当前版本和规则集存在。
2. 把该策略其他版本的 `isCurrent` 置为 false。
3. 把当前版本状态更新为 `PUBLISHED`。
4. 写 `publishedAt`、`publishedBy`、`changeSummary`。
5. 把策略状态改为 `ENABLED`，除非策略已归档。
6. 同步定时任务。

执行模式会优先使用已发布版本；模拟模式可以使用当前编辑版本。

## 7. 复制和回滚

复制策略会基于当前版本创建一个新策略和新的编辑版本。

回滚策略会把目标版本的规则复制成一个新版本，并直接标记为 `PUBLISHED`，再更新策略当前版本和最新版本号。

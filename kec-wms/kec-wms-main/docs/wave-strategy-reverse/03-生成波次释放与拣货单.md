# 生成波次释放与拣货单

## 1. 模拟和执行的差异

`SIMULATE`（模拟）模式：

- 不创建 `wave`
- 不更新出库订单
- 只写运行记录和订单命中结果
- `createdWaveCount` 是估算值

`EXECUTE`（执行）模式：

- 创建 `wave`
- 创建 `wave_order`
- 更新 `outbound_order.waveId` 和策略上下文
- 写 `outbound_order_wave_context`
- 如果释放模式是立即释放，会调用 `releaseWave`（释放波次）

## 2. 生成 wave

执行模式下，每个规划波次会创建一条 `wave`：

- `sourceType = STRATEGY`
- `strategyId`
- `strategyVersionId`
- `strategyRunId`
- `waveTypeCode`
- `pickMode`
- `downstreamMode`
- `releaseMode`
- `batchNo`
- `status = CREATED`
- `priority`
- 订单数、行数、总数量、SKU（商品）数
- `configSnapshot`：策略版本配置快照

波次号按仓库编码和日期生成前缀，再用当日最大序号递增。

## 3. 订单进入波次

每个命中的订单会：

- 写入 `wave_order`
- 更新 `outbound_order.waveId`
- 更新 `outbound_order.waveStrategyId`
- 更新 `outbound_order.waveStrategyVersionId`
- 更新 `outbound_order.waveTypeCode`
- 更新 `outbound_order.downstreamMode`
- 状态更新为 `IN_WAVE`
- upsert（插入或更新）`outbound_order_wave_context`

`outbound_order_wave_context` 会保存本次运行 ID（标识）、批次号、拣货模式、释放模式、释放状态和分类快照。

## 4. 释放波次

`releaseWave`（释放波次）会把波次转换成拣货任务：

1. 查询波次和订单。
2. 查询订单的库存分配明细。
3. 按库位所属库区和 `pickConfig.crossZoneSplitMode`（跨库区拆分模式）分组。
4. 如果启用最大订单限制，再按订单数量拆分拣货单。
5. 创建 `pick_order`。
6. 创建拣货单行。
7. 波次状态更新为 `RELEASED`。
8. 订单状态从 `IN_WAVE`、`ALLOCATED`、`PENDING_WAVE` 推进到后续待拣货状态。
9. 写波次和订单操作日志。

## 5. 拣货单字段映射

释放时，拣货单会继承波次策略上下文：

- `waveId`
- `strategyRunId`
- `waveTypeCode`
- `taskType`
- `priority`
- `pickMode`
- `downstreamMode`

这也是后续 PDA（手持端）拣货和 Web（网页）拣货能识别任务类型、拣货模式、下游模式的来源。

## 6. 释放模式

当前释放模式来自 `releaseConfig.releaseMode`：

- `MANUAL`：执行策略只创建波次，后续由人工释放
- `IMMEDIATE`：执行策略创建波次后立即释放为拣货单

# 运行记录与风险边界

## 1. 运行记录

每次模拟或执行都会创建 `wave_strategy_run`：

- 租户
- 仓库
- 策略
- 策略版本
- 运行模式
- 触发方式
- 触发人
- 请求载荷
- 候选订单数
- 命中订单数
- 被高优先级占用数
- 未分类订单数
- 创建波次数
- 创建拣货单数
- 运行状态
- 完成时间

每个候选订单会写 `wave_strategy_run_order`，包括：

- 是否命中策略
- 被哪个高优先级策略占用
- 波次类型
- 拣货模式
- 下游模式
- 结果状态
- 规则命中快照

## 2. 常见结果状态

当前代码里常见结果状态：

- `MATCHED`：模拟命中
- `SKIPPED`：跳过，例如筛选条件不匹配或被高优先级策略占用
- `UNCLASSIFIED`：未分类，例如没有可用波次类型或低于最小成波数

原因码会写入 `matchedRuleSnapshot`（命中规则快照），再由 `reason-codes.ts` 做分类和翻译。

## 3. 优先级风险

当前高优先级处理是运行期规则判断，不是数据库级全局锁：

- 当前策略会跳过命中更高优先级策略的订单。
- 同优先级策略之间没有天然抢占顺序。
- 如果两个同优先级策略并发执行，都可能读取到 `waveId = null` 的同一批订单。

因此同优先级并发执行仍需要额外保护，例如更新订单时增加 `waveId is null`（波次为空）条件，或引入更强的并发锁策略。

## 4. 候选订单边界

波次策略只处理：

- 已完成库存分配的订单
- 状态为 `ALLOCATED` 或 `PENDING_WAVE`
- 当前没有 `waveId`

未分配库存、已进入波次、已拣货或更后置状态的订单不会被候选查询捞出。

## 5. 波次类型边界

波次类型启用状态会影响分类：

- 如果目标波次类型未启用，订单会无法分类。
- 如果订单结构不属于当前支持的三类订单结构，也会无法分类。
- 热销和固定组合都依赖当前执行批次内统计，不是全局历史销量。

## 6. 排查建议

排查波次策略时按这个顺序看：

1. `wave_strategy` 是否 `ENABLED`，优先级是否符合预期。
2. 当前版本是否已 `PUBLISHED`。
3. `wave_strategy_rule_set` 的筛选、执行、波次类型、释放配置是否正确。
4. 候选订单是否满足 `waveId = null` 和状态条件。
5. `wave_strategy_run_order.matchedRuleSnapshot` 的原因码。
6. 如果已执行，检查 `wave`、`wave_order`、`outbound_order.waveId` 和 `outbound_order_wave_context`。
7. 如果已释放，继续检查 `pick_order` 和拣货单行。

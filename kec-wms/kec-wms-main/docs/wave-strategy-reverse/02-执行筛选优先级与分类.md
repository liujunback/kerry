# 执行筛选优先级与分类

## 1. 候选订单

执行入口：

- `simulateWaveStrategy`（模拟波次策略）
- `executeWaveStrategy`（执行波次策略）
- `runWaveStrategy`（运行波次策略核心函数）

候选订单基础条件：

- 同租户
- 同仓库
- `waveId = null`
- 状态为 `ALLOCATED` 或 `PENDING_WAVE`

如果请求指定 `orderIds`，则只在指定订单内筛选。

## 2. 筛选条件

筛选配置支持两种方式：

- 旧式数组字段，例如业务类型、客户、平台、运输方式、预期出库时间、库区
- 结构化条件组 `conditionGroups`

如果存在结构化条件组，执行时以结构化条件组为主。条件组支持组内逻辑和组间逻辑，结果会写入运行订单的 `matchedRuleSnapshot`（命中规则快照）。

## 3. 优先级抢占

策略优先级使用数值越小优先级越高的规则。

执行当前策略前，会加载同仓库下：

- 状态为 `ENABLED`
- 未删除
- `priority < currentPriority`
- 不是当前策略

然后用这些高优先级策略的筛选条件先判断候选订单。如果订单命中高优先级策略，当前策略会把该订单标记为 `CLAIMED_BY_HIGHER_PRIORITY`（被高优先级策略占用），不再纳入本次波次规划。

这个逻辑是“高优先级先认领”，不是全局串行锁。

## 4. 执行批次

剩余可执行订单会按 `executionConfig`（执行配置）排序：

- 排序字段支持 `expectedOutboundTime`（预计出库时间）和 `createdAt`（创建时间）
- 排序方向支持升序或降序
- 如果启用 `maxOrdersPerRun`（每次运行最大订单数），会切成多个执行批次

后续波次分类和规划按执行批次分别处理。

## 5. 六类波次类型

当前分类顺序：

- `SINGLE_ONE_HOT`
- `SINGLE_MULTI_HOT`
- `SINGLE_ONE_NORMAL`
- `SINGLE_MULTI_NORMAL`
- `MULTI_FIXED_COMBO`
- `MULTI_NON_FIXED`

分类逻辑：

- `SINGLE_ITEM_SINGLE`（单件单品）优先判断 `SINGLE_ONE_HOT`，否则 `SINGLE_ONE_NORMAL`
- `SINGLE_ITEM_MULTI`（单件多品）优先判断 `SINGLE_MULTI_HOT`，否则 `SINGLE_MULTI_NORMAL`
- `MULTI_ITEM`（多件订单）优先判断 `MULTI_FIXED_COMBO`，否则 `MULTI_NON_FIXED`

热销命中不是直接看手工 `hotSkuIds`（热销商品ID列表）本身，而是当前执行批次内同主 SKU（商品）订单数是否达到该波次类型的最小成波数。

固定组合命中使用两 SKU（商品）签名统计，达到最小成波数才归为固定组合。

## 6. 成波数量

每类波次类型有：

- `minOrdersPerWave`：最小成波订单数
- `maxOrdersPerWave`：最大成波订单数

规划波次时，低于最小成波数的尾批会被释放为 `WAVE_SIZE_BELOW_MINIMUM`（低于最小成波数），不会创建 wave（波次）。

当前代码还对 `SINGLE_ONE_HOT`（单件单品热销）尾批做回退：如果热销尾批不足最小成波数，会回退到 `SINGLE_ONE_NORMAL`（单件单品普通）再规划。

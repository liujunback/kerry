# 库存冻结与解冻功能说明

## 概述

库存冻结/解冻是 WMS 系统中用于临时控制库存可用性的功能。通过冻结操作，可以将可用库存（AVAILABLE）转换为冻结库存（FROZEN），使其暂时不可用于订单分配；通过解冻操作，可以将冻结库存恢复为可用状态。

## 核心特性

### 1. 不锁定库位

- **冻结操作**：只改变库存状态（AVAILABLE → FROZEN），不锁定库位
- **库位可用性**：冻结后的库位仍然可以继续收货、上架
- **与库位锁定的区别**：库位锁定（lockStatus）会阻止所有库位操作，而冻结只影响库存的可分配性

### 2. 状态转换

```
冻结流程：
AVAILABLE (可用) → FROZEN (冻结)
- 减少 AVAILABLE 桶数量
- 增加 FROZEN 桶数量
- 库位状态不变

解冻流程：
FROZEN (冻结) → AVAILABLE (可用)
- 减少 FROZEN 桶数量
- 增加 AVAILABLE 桶数量
- 库位状态不变
```

### 3. 业务场景

**冻结场景**：
- 质量问题待检：商品需要质检，暂时不能发货
- 临期商品：接近保质期，需要特殊处理
- 客户要求：客户要求暂停发货
- 库存盘点：盘点期间暂停分配
- 召回处理：产品召回，需要冻结相关批次

**解冻场景**：
- 质检通过：质量检验合格，恢复可用
- 问题解决：临期商品已处理，可以继续销售
- 客户确认：客户同意继续发货
- 盘点完成：盘点结束，恢复正常
- 召回取消：召回取消，恢复销售

## 功能实现

### 后端 API

#### 1. 冻结库存

```
POST /api/v1/inventory/freezes
```

**请求体**：
```json
{
  "warehouseId": "warehouse-uuid",
  "freezeType": "MANUAL_HOLD",
  "reason": "质量问题待检",
  "lines": [{
    "skuId": "sku-uuid",
    "locationId": "location-uuid",
    "batchNumber": "BATCH001",
    "lpn": "LPN001",
    "quantity": 100,
    "reason": "质量问题待检"
  }]
}
```

**冻结类型（freezeType）**：
- `QC_HOLD`：质量冻结
- `DEFECTIVE_HOLD`：不良品冻结
- `EXPIRY_HOLD`：过期冻结
- `RECALL_HOLD`：召回冻结
- `COUNT_HOLD`：盘点冻结
- `MANUAL_HOLD`：手动冻结

**响应**：
```json
{
  "data": [{
    "skuId": "sku-uuid",
    "locationId": "location-uuid",
    "quantity": 100
  }]
}
```

#### 2. 解冻库存

```
POST /api/v1/inventory/freezes/{bucketId}/release
```

**请求体**：
```json
{
  "releaseType": "RELEASE",
  "quantity": 100,
  "reason": "质检通过"
}
```

**解冻类型（releaseType）**：
- `RELEASE`：解冻为可用库存
- `TO_DEFECTIVE`：转为不良品
- `SCRAP`：报废

**响应**：
```json
{
  "data": {
    "id": "bucket-uuid",
    "quantity": 0,
    "bucketType": "FROZEN"
  },
  "message": "Released 100 units from frozen inventory"
}
```

#### 3. 查询冻结库存

```
GET /api/v1/inventory/freezes?warehouseId={id}&page=1&pageSize=10
```

**响应**：
```json
{
```

### 服务层实现

#### 冻结服务

[inventory-operation-service.ts](../backend/src/lib/services/inventory-operation-service.ts)

```typescript
export async function freeze(params: FreezeParams, tx?: TransactionClient) {
  // 1. 检查 AVAILABLE 桶是否有足够库存
  const availableBucket = await getBucket({
    tenantId: params.tenantId,
    warehouseId: params.warehouseId,
    locationId: params.locationId,
    skuId: params.skuId,
    batchNumber: params.batchNumber,
    lpn: params.lpn,
    bucketType: BucketType.AVAILABLE,
  })

  if (!availableBucket || availableBucket.quantity < params.quantity) {
    throw new Error('可用库存不足')
  }

  // 2. 创建冻结事件（Event Sourcing）
  await createFreezeEvents({
    // ... 事件参数
  }, client)

  // 3. 更新桶状态
  await updateBucketsInTransaction([
    {
      // 减少 AVAILABLE 桶
      bucketType: BucketType.AVAILABLE,
      quantityDelta: -params.quantity,
    },
    {
      // 增加 FROZEN 桶
      bucketType: BucketType.FROZEN,
      quantityDelta: params.quantity,
    },
  ], client)

  // 4. 更新库存快照
  await updateInventorySnapshots(...)
}
```

```typescript
  await updateInventorySnapshots(...)
}
```

## 业务规则

### 1. 冻结规则

- **只能冻结可用库存**：只有 AVAILABLE 类型的库存可以被冻结
- **数量限制**：冻结数量不能超过可用库存数量
- **批次保持**：冻结后保留原批次号和效期信息
- **库位不变**：冻结不改变库位，库存仍在原库位
- **不锁定库位**：库位的 lockStatus 保持不变

### 2. 解冻规则

- **只能解冻冻结库存**：只有 FROZEN 类型的库存可以被解冻
- **数量限制**：解冻数量不能超过冻结库存数量
- **批次保持**：解冻后保留原批次号和效期信息
- **库位不变**：解冻不改变库位，库存仍在原库位
- **恢复可用**：解冻后库存变为 AVAILABLE，可以用于订单分配

### 3. 与订单分配的关系

- **冻结库存不可分配**：FROZEN 类型的库存不会被订单分配逻辑选中
- **已分配库存不可冻结**：ALLOCATED 类型的库存不能被冻结（已锁定给订单）
- **解冻后可分配**：解冻为 AVAILABLE 后，库存可以正常参与订单分配

## 事务保证

所有冻结/解冻操作都在数据库事务中完成，确保数据一致性：

```typescript
await prisma.$transaction(async (tx) => {
  // 1. 创建库存事件（Event Sourcing）
  await createFreezeEvents(...)

  // 2. 更新库存桶
  await updateBucketsInTransaction(...)

  // 3. 更新库存快照
  await updateInventorySnapshots(...)
})
```

如果任何步骤失败，整个事务会回滚，保证数据一致性。

## 常见问题

### Q1: 冻结和库位锁定有什么区别？

**A**:
- **冻结（Freeze）**：只改变库存状态，不影响库位。冻结后库位仍可收货、上架，但库存不可分配。
- **库位锁定（Lock）**：锁定整个库位，所有操作都被阻止，包括收货、上架、拣货等。

### Q2: 冻结库存会影响库存快照吗？

**A**: 会。冻结操作会更新库存快照：
- `qtyAvailable` 减少
- `qtyFrozen` 增加
- `totalOnHand` 不变（总库存不变）

### Q3: 可以部分解冻吗？

**A**: 可以。解冻时可以指定数量，不需要全部解冻。例如冻结了 100 件，可以先解冻 50 件。

### Q4: 冻结库存可以直接转为不良品吗？

**A**: 可以。解冻时可以选择 `releaseType: 'TO_DEFECTIVE'`，将冻结库存直接转为不良品，而不是恢复为可用库存。

### Q5: 冻结操作是否需要审批？

**A**: 当前实现是直接执行，不需要审批。如果业务需要审批流程，可以参考调整单的审批机制进行扩展。

# 物流渠道

## 一、功能概述

物流渠道用于维护 WMS 出库作业可使用的物流渠道配置，覆盖渠道主档、国家配置、仓库配置、作业规则和限制规则。

本模块的目标是将旧系统 `logistics_providers` 中混合在同一张表里的渠道编码、接口集成、面单规则、关箱发货、多包裹、箱唛、账号参数和限制条件拆分为清晰的功能层级，便于多国家、多仓库独立配置和上线切换。

## 二、业务范围

### 2.1 覆盖范围

- 维护物流渠道基础信息
- 按国家维护渠道可用范围和默认配置
- 按仓库维护渠道启停状态和仓库级配置
- 维护物流集成参数模板
- 维护面单、追踪号、关箱发货、多包裹、箱唛等作业规则
- 维护重量、尺寸、目的国家、特殊平台取消等限制规则
- 支持从旧系统物流渠道配置迁移到新系统结构

### 2.2 暂不覆盖范围

- 不设计对外接口
- 不设计权限矩阵
- 不设计审计日志
- 不设计运费计算
- 不设计物流路由优先级
- 不设计 SLA 时效承诺
- 不设计客户报价和计费规则

## 三、核心术语

### 3.1 物流渠道

物流渠道是 WMS 出库单实际发货时选择的承运方式或服务线路。

示例：

- `KEngine-ETFRFRS20`
- `KEngine-CADEEUS90`
- `Kerry-TH`
- `J&T`
- `SELFPICK`
- `B2BDELIVERY`
- `LAZADA官方物流`

### 3.2 渠道类型

渠道类型用于描述物流渠道的作业模式，不直接等同于旧系统的 `Slug`。

建议类型：

- **API集成**：通过物流集成服务创建运单、获取面单或回传发货
- **平台物流**：由平台指定或平台侧承接的物流渠道
- **自提**：客户、门店或内部人员自行提货
- **线下运输**：不通过标准 API 创建物流单的人工运输渠道
- **B2B配送**：面向批发、门店、经销商等 B2B 场景的配送渠道
- **测试渠道**：仅用于测试环境或上线验证，不参与正式业务

### 3.3 国家

国家表示该渠道配置归属的 WMS 运营国家或区域。

示例：

- `DE`
- `FR`
- `GB`
- `TH`
- `VN`

国家不是目的国家。目的国家属于限制规则或服务范围配置。

### 3.4 仓库

仓库表示该物流渠道在哪个仓库可用。

同一个国家下可以有多个仓库，同一个物流渠道可以在不同仓库独立启用、停用或配置不同作业规则。

### 3.5 状态

状态表示渠道在指定仓库下是否可被出库作业选择。

建议状态：

- **启用**：可被出库单选择和使用
- **停用**：不可被新出库单选择
- **测试**：仅用于测试单或上线验证

旧系统的 `Is Api Enabled` 不能直接作为状态迁移。它只表示是否启用 API 能力。

## 四、四层配置结构

### 4.1 第一层：基础信息

基础信息定义物流渠道是什么，以及它属于哪个国家和仓库使用范围。

#### 字段说明

- **Code**
  - 渠道唯一编码
  - 从旧系统 `Code` 迁移
  - 同一租户内唯一

- **Name**
  - 渠道展示名称
  - 从旧系统 `Name` 迁移

- **类型**
  - 用于决定渠道作业模式
  - 例如 API集成、自提、平台物流、线下运输、B2B配送、测试渠道

- **国家**
  - 表示该配置归属的运营国家
  - 优先从旧系统文件名迁移，例如 `TH.logistics_providers.csv` 迁移为 `TH`

- **仓库**
  - 表示该渠道在哪个仓可用
  - 旧系统没有显式仓库字段，迁移时需要按上线范围补齐

- **状态**
  - 控制该仓库下渠道是否可用
  - 新系统必须独立维护，不从 `Is Api Enabled` 直接继承

#### 应用规则

- 出库单选择物流渠道时，按 `仓库 + 状态 = 启用` 过滤。
- 渠道列表维护时，可按国家、仓库、类型、状态筛选。
- 同一 `Code` 可以在多个仓库配置，但仓库级状态互不影响。
- 测试渠道默认不进入正式出库渠道选择范围。

### 4.2 第二层：集成配置

集成配置定义该渠道如何与物流服务、平台或内部系统协作。

#### 字段说明

- **集成类型**
  - 从渠道类型进一步落到技术集成方式
  - 示例：`kecengine`、`kparcel`、`dhlexpress`、`fedex`、`selfpick`
  - 新系统不直接照搬旧系统 `Slug`，需要收敛为标准枚举

- **物流执行代理编码**
  - 实际代理、承运商或内部渠道标识
  - 从旧系统 `Agent` 迁移

- **是否启用 API**
  - 从旧系统 `Is Api Enabled` 迁移
  - 表示是否通过 API 创建或处理物流单

- **是否启用 API 校验**
  - 从旧系统 `Is Api Validation` 迁移
  - 表示出库前是否需要进行渠道参数校验

- **账号参数模板**
  - 从旧系统 `Account Profile` 迁移
  - 用于维护账号、Token、客户号、计费账号等字段定义

- **服务参数模板**
  - 从旧系统 `Service Profile` 迁移
  - 用于维护产品代码、渠道代码、运输类型、贸易条款等字段定义

- **扩展字段**
  - 从旧系统 `Fields` 迁移
  - 用于承载少量渠道特殊字段

#### 应用规则

- `API集成` 类型的渠道必须维护集成类型、物流执行代理编码和必要账号参数。
- `自提`、`线下运输` 可以不启用 API，但仍可配置面单或交接规则。
- `平台物流` 可根据平台作业方式决定是否维护账号参数。
- 账号参数和服务参数只描述配置项，不在渠道列表中直接展开展示全部字段。

#### 集成类型枚举

新系统第一版集成类型建议收敛为以下枚举：

- **KEngine集成**
  - 适用于旧系统 `Slug = kecengine`
  - 表示通过 KEngine 物流集成服务处理物流单、面单或追踪号

- **KEC集成**
  - 适用于旧系统 `Slug = kec`
  - 表示通过 KEC 内部物流能力处理

- **K-Parcel集成**
  - 适用于旧系统 `Slug = kparcel`
  - 表示通过 K-Parcel 能力处理托盘、箱唛或包裹交接

- **KECTM集成**
  - 适用于旧系统 `Slug = KECTM / kectm`
  - 表示通过 KECTM 物流能力处理

- **承运商直连**
  - 适用于 DHL、FedEx、SF、DPEX、NinjaVan、Bring、BOXC、KerryHK 等承运商类集成
  - 旧系统可能表现为 `Slug = dhlexpress / dhlecommerce / fedex / sf / dpex / dpexline / ninjavan / bring / boxc / kerryhk / smooth`

- **自提**
  - 适用于旧系统 `Slug = SELFPICK`
  - 表示客户、门店、内部人员或指定对象自行提货

- **B2B/线下**
  - 适用于旧系统 `Slug = B2B / TRUCK`
  - 表示不通过标准物流 API 的 B2B 配送、线下运输或人工交接

- **平台/无集成**
  - 适用于平台物流、空 `Slug` 或不需要系统直连物流接口的渠道
  - 空 `Slug` 不直接等于平台/无集成，迁移时需结合 `Code`、`Name`、物流执行代理编码确认

#### 旧系统 Slug 迁移映射

```text
kecengine                 → KEngine集成
kec                       → KEC集成
kparcel                   → K-Parcel集成
KECTM / kectm             → KECTM集成
SELFPICK                  → 自提
B2B / TRUCK               → B2B/线下
dhlexpress / dhlecommerce → 承运商直连
fedex / sf / dpex         → 承运商直连
dpexline / ninjavan       → 承运商直连
bring / boxc / kerryhk    → 承运商直连
smooth / EXPRESS / CN-HK  → 承运商直连
空值                      → 平台/无集成 或人工确认
```

#### 集成类型使用规则

- 集成类型用于决定系统调用哪类物流处理能力。
- 集成类型不等同于渠道类型。
- 渠道类型描述业务作业模式，例如 API集成、自提、平台物流。
- 集成类型描述技术或执行通道，例如 KEngine集成、承运商直连、平台/无集成。
- 旧系统空 `Slug` 的渠道必须人工确认，不允许批量默认归为 KEngine集成。

### 4.3 第三层：作业规则

作业规则定义该物流渠道在 WMS 出库流程中的行为。

#### 字段说明

- **是否每包打印面单**
  - 从旧系统 `Is Print Label On Each Pack` 迁移

- **是否关箱发送物流单**
  - 从旧系统 `Is Send Shipment On Each Close Box` 迁移

- **追踪号来源**
  - 从旧系统 `Tracking Number Source` 迁移
  - 示例：`tracking_number`、`tracking_number2`

- **是否使用订单号作为追踪号**
  - 从旧系统 `Is Tracking Number From Order Number` 迁移

- **是否使用 API 临时追踪号**
  - 从旧系统 `Is Use Api Temp Tracking Number` 迁移

- **是否由数据源返回追踪号和面单**
  - 从旧系统 `Is Tracking Number And Label From Datasource` 迁移

- **是否使用原始面单 URL**
  - 从旧系统 `Is Using Original Label Url` 迁移

- **面单模板**
  - 从旧系统 `Label Class` 迁移
  - 用于自提、B2B、特殊渠道等非标准面单模板

- **是否支持多包裹**
  - 从旧系统 `Is Support Multiple Parcels` 迁移

- **是否生成箱唛**
  - 从旧系统 `Is Generate Box Label` 迁移

- **托盘/箱唛模板**
  - 从旧系统 `Pallet Label Template`、`K-Parcel Pallet Settings` 迁移

- **组箱明细推送目标**
  - 从旧系统 `组箱明细推送OPS系统` 迁移

#### 应用规则

- 若渠道不支持多包裹，打包时不允许一个出库单生成多个包裹。
- 若启用关箱发送物流单，则关箱动作完成后触发物流单创建或发货确认。
- 若启用每包打印面单，则每个包裹都必须生成可打印面单。
- 若面单来自外部数据源，则系统不应强制使用本地模板生成承运商面单。
- 若配置箱唛模板，则组托、装箱或交接环节可打印对应标签。

### 4.4 第四层：限制规则

限制规则定义物流渠道是否允许承接某类包裹或订单。

#### 字段说明

- **重量限制**
  - 从旧系统 `Weight Limit (kg)` 迁移
  - `0.000` 视为未配置有效限制

- **包裹限制规则**
  - 从旧系统 `Package Limit Rules (JSON)` 迁移
  - 可表达国家、重量、尺寸、件数等区间限制

- **是否校验收件国家**
  - 从旧系统 `Is Verify Consignee Country` 迁移

- **追踪号长度**
  - 从旧系统 `Tracking Number Length` 迁移

- **跳过追踪号格式规则**
  - 从旧系统 `Is Skip Specific Format Tracking Number`、`Skip Prefix Number`、`Skip Suffix Number` 迁移

- **平台取消物流单**
  - 从旧系统 `Cancel Shipment For Platform` 迁移

- **装箱/分拣特殊限制**
  - 从旧系统 `自动分拣箱子类型` 迁移

#### 应用规则

- 若配置重量限制，打包称重后超过限制的包裹不可使用该渠道。
- 若配置目的国家校验，收件国家不匹配时不可使用该渠道。
- 若配置包裹尺寸或件数规则，打包完成后进行校验。
- 若配置追踪号格式规则，获取或录入追踪号时进行校验。
- 限制规则只决定渠道是否可用，不负责计算运费。

## 六、状态与使用规则

### 6.1 渠道状态

```text
测试 → 启用 → 停用
  └────────→ 停用
```

### 6.2 状态说明

- **测试**
  - 仅用于测试订单或上线验证
  - 不进入正式出库渠道选择范围

- **启用**
  - 可被正式出库单选择
  - 可参与打包、面单、关箱、发货流程

- **停用**
  - 不可被新出库单选择
  - 已经使用该渠道的历史订单保留原渠道信息

### 6.3 出库选择规则

出库选择物流渠道时，应按以下顺序过滤：

```text
当前仓库
  → 状态 = 启用
  → 渠道类型匹配
  → 作业规则满足
  → 限制规则满足
  → 可选择渠道
```

## 七、旧系统字段迁移口径

### 7.1 基础信息

- `Code` → Code
- `Name` → Name
- `Slug` → 集成类型，同时辅助判断类型
- `Agent` → 物流执行代理编码
- 文件名 `DE/FR/GB/TH/VN/FY` → 国家
- 仓库 → 旧系统无字段，迁移时按实际上线仓库补齐
- 状态 → 新系统新增字段，不从旧系统直接迁移

### 7.2 集成配置

- `Is Api Enabled` → 是否启用 API
- `Is Api Validation` → 是否启用 API 校验
- `Validation Slug` → Validation Slug
- `Sorting Code` → Sorting Code
- `Account Profile` → 账号参数模板
- `Service Profile` → 服务参数模板
- `Fields` → 扩展字段

### 7.3 作业规则

- `Is Print Label On Each Pack` → 是否每包打印面单
- `Is Send Shipment On Each Close Box` → 是否关箱发送物流单
- `Is Tracking Number From Order Number` → 是否使用订单号作为追踪号
- `Is Use Api Temp Tracking Number` → 是否使用 API 临时追踪号
- `Is Tracking Number And Label From Datasource` → 是否由数据源返回追踪号和面单
- `Is Using Original Label Url` → 是否使用原始面单 URL
- `Label Class` → 面单模板
- `Tracking Number Source` → 追踪号来源
- `Is Support Multiple Parcels` → 是否支持多包裹
- `Is Generate Box Label` → 是否生成箱唛
- `Pallet Label Template` → 托盘/箱唛模板
- `K-Parcel Pallet Settings` → K-Parcel 托盘配置
- `组箱明细推送OPS系统` → 组箱明细推送目标

### 7.4 限制规则

- `Weight Limit (kg)` → 重量限制
- `Package Limit Rules (JSON)` → 包裹限制规则
- `Is Verify Consignee Country` → 是否校验收件国家
- `Tracking Number Length` → 追踪号长度
- `Is Skip Specific Format Tracking Number` → 是否跳过特定追踪号格式
- `Skip Prefix Number` → 跳过前缀位数
- `Skip Suffix Number` → 跳过后缀位数
- `Cancel Shipment For Platform` → 平台取消物流单
- `自动分拣箱子类型` → 自动分拣箱子类型

## 八、关键业务规则

### 8.1 类型应用规则

- 类型用于决定渠道作业模式，不用于判断技术集成方式。
- `API集成` 渠道通常需要账号参数和服务参数。
- `自提` 渠道可以不启用 API，但可以配置面单模板。
- `平台物流` 渠道可以不直接创建物流单，但需要保留平台物流编码。
- `线下运输` 渠道可以不生成承运商面单。
- `测试渠道` 不进入正式出库渠道选择范围。

### 8.2 国家应用规则

- 国家表示配置归属的运营区域。
- 国家用于页面筛选、配置隔离和上线迁移。
- 国家不等于目的国家。
- 目的国家限制应放在限制规则中维护。

### 8.3 仓库应用规则

- 仓库决定渠道是否可被当前仓使用。
- 同一渠道在不同仓库可以配置不同状态。
- 同一渠道在不同仓库可以配置不同账号参数、作业规则和限制规则。
- 新仓上线时，可以从同国家已有仓库复制渠道配置，再调整状态和参数。

### 8.4 状态应用规则

- 只有 `启用` 状态的仓库渠道可被正式出库单选择。
- `停用` 不影响历史订单查询。
- `测试` 仅用于测试单或上线验证。
- 旧系统没有独立状态字段，迁移时需要人工确认默认状态。

## 九、字段收敛清单

### 9.1 第一版保留字段

第一版物流渠道配置保留以下字段，作为页面和配置模型的主字段。

#### 基础信息

- Code
- Name
- 类型
- 国家
- 仓库
- 状态
- 备注

#### 集成配置

- 集成类型
- 物流执行代理编码
- 是否启用 API
- 是否启用 API 校验
- 账号参数模板
- 服务参数模板
- 扩展字段

#### 作业规则

- 是否每包打印面单
- 是否关箱发送物流单
- 是否支持多包裹
- 追踪号生成方式
- 追踪号来源
- 面单来源
- 面单模板
- 是否生成箱唛
- 箱唛模板

#### 限制规则

- 重量限制
- 包裹限制规则
- 是否校验收件国家
- 目的国家规则
- 追踪号格式规则

### 9.2 高级字段

以下字段不放在列表主字段中，仅在渠道详情的高级配置中维护。

- Validation Slug
- Sorting Code
- 是否使用 API 临时追踪号
- 是否使用订单号作为追踪号
- 是否由数据源返回追踪号和面单
- 是否使用原始面单 URL
- K-Parcel 托盘配置
- 组箱明细推送目标
- 追踪号长度

- 跳过追踪号后缀位数
- 平台取消物流单
- 自动分拣箱子类型

### 9.3 不再保留为结构化字段

以下旧系统字段不作为新系统物流渠道结构化字段保留。

- Carrier
- Color
- Invoice Qty
- Handover Remarks
- Notification Emails
- Is Add Logistics Code At Bottom Of Waybill Label
- Is Increment Parent Child Tracking Number
- Is Generate Temp Tracking Number
- Is Custom Tracking Number Format

处理方式：

- 如确有历史数据需要保留，可进入备注或扩展字段。
- 不进入列表页。
- 不作为第一版必填配置。
- 不参与出库渠道可用性判断。

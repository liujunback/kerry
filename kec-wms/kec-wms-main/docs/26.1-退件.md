## 1. 业务范围

本文档定义 WMS 侧退件作业功能，覆盖买家退件和快递退件从签收到完成的仓内执行流程。

当前版本只关注仓内作业，不考虑退件权限、接口设计、运营看板、报表分析。

### 1.1 退件类型

| 退件类型 | 枚举值 | 说明 | 创建方式 |
|---|---|---|---|
| 买家退件 | `BUYER_RETURN` | 已有预报退件单的买家退货包裹 | 扫描物流单号后匹配预报退件单 |
| 快递退件 | `COURIER_RETURN` | 未匹配到预报退件单，但可根据物流单号找到原出库订单的退回包裹 | 签收时由系统根据原出库订单自动创建退件单，仓库选择类型 |

### 1.2 主流程

```text
签收
  ↓
清点
  ↓
等待客户下达处理方式
  ↓
根据处理方式生成上架单
  ↓
上架
  ↓
完成
```

### 1.3 流程边界

- WMS 负责签收、清点、容器绑定、退件暂存、生成上架单、上架和状态维护。
- OMS 或客户系统负责根据清点结果下达处理方式。
- 清点完成后，商品先暂存在指定退件库位，不直接进入可用库存。
- WMS 收到客户处理方式后，人工筛选已下达处理策略的退件单生成上架单。

## 2. 退件签收

### 2.1 签收入口

签收入口为扫描物流单号。

```text
扫描物流单号
  ↓
按物流单号匹配预报退件单
  ├─ 匹配成功：签收成功，类型为买家退件
  ↓
匹配失败
  ↓
按物流单号查找出库订单号 / 平台订单号
  ├─ 找到订单：仓库选择快递退件，系统自动创建退件单，签收成功
  └─ 找不到订单：不允许签收
```

### 2.2 买家退件签收

1. 操作员扫描物流单号。
2. 系统根据物流单号匹配预报退件单号。
3. 匹配成功后，系统加载预报退件单信息。
4. 操作员确认签收。
5. 系统将退件单状态更新为 `SIGNED`。

### 2.3 快递退件签收

1. 操作员扫描物流单号。
2. 系统未匹配到预报退件单。
3. 系统根据物流单号查找出库订单号或平台订单号。
4. 如果找到原出库订单，系统展示订单基础信息。
5. 仓库选择退件类型为 `快递退件`。
6. 系统根据原出库订单自动创建退件单。
7. 系统完成签收，退件单状态更新为 `SIGNED`。

### 2.4 签收规则

- 同一仓库内，同一物流单号只能存在一个有效退件单。
- 预报退件单匹配优先级高于原出库订单匹配。
- 快递退件必须能根据物流单号找到原出库订单号或平台订单号。
- 无法匹配预报退件单且无法匹配原出库订单时，不允许签收。
- 快递退件自动创建退件单时，SKU 信息来源于原出库订单。

## 3. 退件清点

### 3.1 清点入口

清点入口为扫描物流单号。

```text
扫描物流单号
  ↓
查找退件单号
  ↓
加载退件单 SKU 信息
  ↓
扫描 barcode
  ↓
录入数量、质量、有效期、batchno
  ↓
damaged 拍照
  ↓
绑定容器号
  ↓
暂存到指定退件库位
  ↓
清点完成
```

### 3.2 清点操作

1. 操作员扫描物流单号。
2. 系统根据物流单号查找退件单号。
3. 系统加载退件单 SKU 信息。
4. 操作员扫描 SKU barcode。
5. 操作员录入清点数量。
6. 操作员选择质量：`good` 或 `damaged`。
7. 如果 SKU 管控有效期，操作员必须录入有效期。
8. 如果 SKU 管控批次，操作员必须录入 `batchno`。
9. 如果质量为 `damaged`，默认必须拍照。
10. 操作员绑定容器号。
11. 操作员将容器暂存到指定退件库位。
12. 清点完成后，WMS 将清点结果返回上游 OMS。

### 3.3 清点规则

- 一个退件单可以包含多个 SKU。
- 同一个 SKU 可以按不同质量拆分为多条清点明细。
- `good` 和 `damaged` 不合并为同一条明细。
- 批次不同或有效期不同的商品必须拆成不同明细。
- 容器号必须在清点完成前绑定。
- 暂存库位必须是退件暂存库位。
- 清点完成后，退件单进入等待客户下达处理方式阶段。

### 3.4 damaged 拍照规则

- `damaged` 商品默认需要拍照。
- 照片绑定到退件单明细。
- 未拍照的 `damaged` 明细不能完成清点。

## 4. 客户处理方式

### 4.1 处理方式来源

清点完成后，客户针对已清点完成的退件单下达处理方式。WMS 收到处理方式后，将退件单明细更新为已下达处理方式。

### 4.2 处理方式

| 处理方式 | 枚举值 | 说明 |
|---|---|---|
| 良品上架 | `GOOD_PUTAWAY` | 将 `good` 商品上架到良品库位，形成可用库存 |
| damaged 上架 | `DAMAGED_PUTAWAY` | 将 `damaged` 商品上架到残品库位或 damaged 库位 |
| 销毁 | `DESTROY` | 将商品移动到销毁暂存库位或销毁区，不形成可售库存 |

### 4.3 处理方式规则

- 只有清点完成的退件单明细可以接收处理方式。
- 处理方式需要明确到退件单明细维度。
- 如果同一明细被拆分为多种处理方式，WMS 需要按处理方式拆分明细。
- 处理方式数量不能超过对应明细的已清点数量。
- 一个退件单可以包含多种处理方式。

## 5. 退件上架

### 5.1 上架单生成

WMS 收到处理方式后，操作员手动筛选已下达处理策略的退件单，生成退件上架单。

```text
筛选已下达处理方式的退件单
  ↓
选择退件单明细
  ↓
生成退件上架单
  ↓
执行上架
```

### 5.2 上架操作

1. 操作员扫描容器号。
2. 系统加载容器内待上架明细。
3. 操作员扫描包裹号。
4. 操作员扫描 SKU 条码。
5. 操作员选择质量：`good` 或 `damaged`。
6. 操作员录入上架数量。
7. 操作员扫描或确认目标库位。
8. 系统校验容器号、包裹号、SKU、质量和数量。
9. 校验通过后完成上架。
10. 退件单所有明细完成后，退件单完成。

### 5.3 上架规则

- 上架必须基于退件上架单执行。
- 上架时扫描的容器号、包裹号、SKU、质量必须与上架单明细一致。
- `GOOD_PUTAWAY` 只能上架 `good` 商品。
- `DAMAGED_PUTAWAY` 只能上架 `damaged` 商品。
- `DESTROY` 上架到销毁暂存库位或销毁区。
- 上架数量可以分多次完成，但累计数量不能超过待上架数量。

## 6. 状态设计

### 6.1 退件单明细状态

退件单明细状态是退件作业的主状态，退件单状态根据明细状态汇总。

| 状态 | 枚举值 | 说明 | 进入条件 |
|---|---|---|---|
| 待签收 | `PENDING_SIGN` | 已有预报退件单，尚未签收 | 预报退件单创建后 |
| 已签收 | `SIGNED` | 包裹已签收，待清点 | 签收成功 |
| 清点中 | `COUNTING` | 正在扫描 SKU 并录入清点结果 | 首次保存清点明细 |
| 待处理方式 | `WAIT_DISPOSITION` | 清点完成，等待客户下达处理方式 | 清点完成 |
| 已下达处理方式 | `DISPOSITION_RECEIVED` | 客户处理方式已下达 | WMS 收到处理方式 |
| 待上架 | `PENDING_PUTAWAY` | 已生成上架单，待上架 | 生成退件上架单 |
| 上架中 | `PUTAWAYING` | 上架单部分执行 | 部分数量已上架 |
| 已完成 | `COMPLETED` | 明细已按处理方式完成 | 数量全部上架或进入销毁区 |

### 6.2 退件单状态汇总

退件单状态根据明细状态自动汇总，不单独人工维护。

| 退件单状态 | 枚举值 | 汇总规则 |
|---|---|---|
| 待签收 | `PENDING_SIGN` | 所有明细均为 `PENDING_SIGN` |
| 已签收 | `SIGNED` | 至少一条明细为 `SIGNED`，且没有更后置状态 |
| 清点中 | `COUNTING` | 任一明细为 `COUNTING` |
| 待处理方式 | `WAIT_DISPOSITION` | 所有需处理明细均为 `WAIT_DISPOSITION` |
| 已下达处理方式 | `DISPOSITION_RECEIVED` | 任一明细为 `DISPOSITION_RECEIVED`，且尚未生成上架单 |
| 待上架 | `PENDING_PUTAWAY` | 任一明细为 `PENDING_PUTAWAY`，且没有上架中的明细 |
| 上架中 | `PUTAWAYING` | 任一明细为 `PUTAWAYING` |
| 已完成 | `COMPLETED` | 所有明细均为 `COMPLETED` |

### 6.3 状态流转

```text
PENDING_SIGN
  ↓
SIGNED
  ↓
COUNTING
  ↓
WAIT_DISPOSITION
  ↓
DISPOSITION_RECEIVED
  ↓
PENDING_PUTAWAY
  ↓
PUTAWAYING
  ↓
COMPLETED
```

## 7. 核心字段

### 7.1 退件单字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `return_no` | 是 | WMS 退件单号 |
| `return_type` | 是 | `BUYER_RETURN` / `COURIER_RETURN` |
| `pre_return_no` | 否 | 预报退件单号 |
| `logistics_no` | 是 | 物流单号 / 包裹号 |
| `outbound_order_no` | 否 | 原出库订单号 |
| `platform_order_no` | 否 | 平台订单号 |
| `warehouse_code` | 是 | 仓库编码 |
| `status` | 是 | 退件单状态 |
| `sign_time` | 否 | 签收时间 |
| `count_complete_time` | 否 | 清点完成时间 |
| `strategy_received_time` | 否 | 收到处理方式时间 |
| `complete_time` | 否 | 完成时间 |

### 7.2 退件单明细字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `return_line_no` | 是 | 退件明细号 |
| `return_no` | 是 | WMS 退件单号 |
| `sku` | 是 | SKU 编码 |
| `barcode` | 是 | SKU 条码 |
| `expected_qty` | 否 | 预报数量 |
| `counted_qty` | 是 | 实际清点数量 |
| `quality` | 是 | `good` / `damaged` |
| `batchno` | 条件必填 | SKU 管控批次时必填 |
| `expire_date` | 条件必填 | SKU 管控有效期时必填 |
| `container_code` | 是 | 容器号 |
| `temp_location_code` | 是 | 退件暂存库位 |
| `photo_urls` | 条件必填 | `damaged` 明细必须拍照 |
| `disposition_action` | 否 | 客户处理方式 |
| `status` | 是 | 明细状态 |

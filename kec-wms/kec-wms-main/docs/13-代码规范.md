# 代码规范

本规范适用于 `kec-wms` 仓库内的前端、后端、脚本与文案文件。

## 基本原则

- 优先保证正确性，其次才是“看起来更简洁”
- 修改必须最小化，只改与当前需求直接相关的内容
- 新代码必须和现有模块风格保持一致，不另起一套写法
- 任何会影响业务状态流转、库存、权限、打印的改动，都必须显式说明风险

## 强制要求

- 所有文本文件必须使用 `UTF-8`，禁止 `UTF-8 BOM`
- 默认行尾使用 `LF`
- `*.bat`、`*.cmd`、`*.ps1` 使用 `CRLF`
- `backend` 的 `lint` 和 `build` 默认会先执行编码检查
- 文案必须写入国际化文件，禁止在业务组件中长期保留硬编码中文

## TypeScript

- 禁止使用 `any` 逃避类型约束，确有必要时必须说明原因并限制作用域
- 优先使用已有领域类型、校验 schema、枚举和值对象，不重复定义近似类型
- 函数返回值不清晰时，显式标注返回类型
- 公共函数命名必须体现行为，不使用 `handleData`、`processItem` 之类空泛命名
- 布尔值命名使用 `is`、`has`、`can`、`should` 前缀

## React / Next.js

- 页面负责组装，业务逻辑优先下沉到 hooks、服务层或工具函数
- 组件单文件过大时，优先拆分子组件或提取纯函数，不堆叠条件渲染
- 表单状态、筛选状态、弹层状态分别管理，避免相互污染
- 不为“性能优化”滥用 `useMemo`、`useCallback`
- 客户端组件只在确实需要浏览器能力时使用 `'use client'`
- 对列表页筛选、详情页加载、弹窗交互，优先延续现有交互模式

## API 与服务层

- API route 只负责参数解析、权限校验、调用服务、返回响应
- 业务规则放在服务层或领域逻辑中，不堆在 route 文件内
- 输入参数必须经过校验，不信任前端传值
- 错误信息要可诊断，但不能泄露敏感内部细节
- 涉及库存、单据状态、幂等逻辑时，必须优先考虑重复请求与并发

## 数据与状态

- 状态字段必须使用已有状态机与枚举定义，禁止写散落的字符串字面量
- 查询参数、筛选参数、持久化键名必须稳定，不能随意变更
- 对金额、数量、重量、体积等字段，统一单位后再计算
- 对时间字段，必须明确时区、展示格式、存储格式

## UI 与文案

- 文案统一进入 `messages/*.json`
- 新增文案时，中英文必须同时补齐
- 占位文案、按钮文案、空状态文案应短而明确，不写模糊描述
- 辅助提示应弱化显示，不抢主操作视觉层级
- 无障碍属性、按钮类型、空态和加载态不能省略

## 样式

- 优先复用现有设计 token、Tailwind 工具类和 UI 组件
- 不通过堆叠大量临时类名解决布局问题；重复样式应抽象
- 颜色表达优先语义化，不直接依赖“看起来差不多”的临时色值
- 响应式改动必须同时检查桌面和移动端基本可用性

## 导入与文件组织

- 导入顺序保持稳定：React / Next、第三方库、项目内模块、相对路径
- 禁止保留未使用的导入、状态、函数、常量
- 公共逻辑放到 `lib/`、`hooks/`、`components/` 对应层级，不放页面文件底部长期堆积
- 一个文件只承担一个主要职责，超过职责边界时必须拆分

## 注释与日志

- 注释只解释“为什么”，不解释显而易见的“做了什么”
- 禁止保留临时调试日志、无意义 TODO、注释掉的大段旧代码
- 日志必须可检索、有上下文，不输出敏感信息

## 测试与验证

- 改动筛选、权限、状态流转、打印、库存相关逻辑后，必须至少做针对性验证
- 能用现有 lint、类型检查、脚本验证的，必须执行
- 如果未执行测试，提交说明里必须明确写出原因

## 变更纪律

- 不覆盖、不回滚、不重写与当前任务无关的用户改动
- 不用命令行直接批量写入中文源码或翻译文案
- 涉及编码或行尾问题时，优先使用仓库内脚本和 `UTF-8` 明确写入
- 涉及 BOM、真实 UTF-8、LF/CRLF 判断时，必须按字节读取，禁止用 `Get-Content`、`cat`、`type` 等文本读取结果作为依据
- 大改动前先确认影响范围；发现仓库已有脏改动时，先判断是否冲突再继续

## 提交前检查

提交前至少确认以下事项：

- 本地 `pre-commit` hook 已启用
- 相关文件通过 `lint`
- 新增文案已补齐中英文
- 没有引入未使用代码
- 没有新增编码、BOM、行尾问题
- 没有把临时调试代码带入提交

## 自动执行

- 根目录 `pre-commit` 会对暂存文件执行编码检查
- `backend` 下暂存的 `js/ts/tsx` 文件会执行 ESLint
- GitHub Actions 会对本次变更涉及的文件重复执行相同检查

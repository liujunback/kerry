# 编码与行尾规范

本仓库对文本文件执行强制规范，避免 Windows 终端、编辑器和 Git 之间的编码不一致导致中文乱码。

## 强制规则

- 所有文本文件必须使用 `UTF-8`，且禁止 `UTF-8 BOM`
- 默认行尾必须是 `LF`
- `*.bat`、`*.cmd`、`*.ps1` 必须使用 `CRLF`
- `backend` 的 `lint` 和 `build` 都会先执行编码检查，失败即中断

## 本地要求

- 使用仓库内的 `.editorconfig`
- VS Code 使用仓库内的 `.vscode/settings.json`
- Windows 终端优先使用仓库提供的 UTF-8 PowerShell 配置：

```powershell
.\scripts\use-utf8.ps1
```

## 读取规范

- 在 PowerShell 中查看源码时，禁止依赖默认编码的裸 `Get-Content`
- 读取源码请显式指定 UTF-8，避免终端把 `UTF-8 without BOM` 误读为本地代码页
- 判断文件是否含 `BOM`、是否为真实 `UTF-8`、以及换行符是 `LF/CRLF` 时，必须按字节读取，不能用文本读取结果当作判断依据
- PowerShell 可用 `Get-Content -AsByteStream` 或 `[System.IO.File]::ReadAllBytes($path)`；Node.js 可用 `readFileSync(path)` 先读取 `Buffer`

```powershell
[System.IO.File]::ReadAllText($path, [System.Text.Encoding]::UTF8)
```

```javascript
readFileSync(path, 'utf8')
```

- 如果终端输出与编辑器显示不一致，以“显式 UTF-8 读取”的结果为准
- 如果问题属于编码/BOM/行尾校验，以“字节读取”的结果为准，而不是终端渲染后的文本
- 在确认读取方式正确前，不要批量修改中文注释、中文报错文案或中文 JSON 文案

## 禁止事项

- 不要在未切到 UTF-8 的 Windows 终端中直接写入中文源码或中文 JSON 文案
- 不要用未显式指定编码的 `Get-Content`、`Set-Content`、`Out-File` 批量改中文文件
- 不要用 `Get-Content`、`cat`、`type` 等文本读取命令去判断真实编码、BOM 或换行符
- 不要把中文文案硬编码到 shell 命令字符串里再回写到源码

## 检查命令

```powershell
cd backend
npm run check:encoding
npm run lint
```

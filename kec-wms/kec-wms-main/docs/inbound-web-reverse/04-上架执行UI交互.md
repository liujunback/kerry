# 上架执行UI交互

## 1. 页面入口

对应页面：

- `/shelving`

对应组件：

- `shelving-page.tsx`
- `shelving-scan-panel.tsx`
- `sku-shelving-panel.tsx`
- `shelving-store.ts`

## 2. 当前页面先做模式分流

页面打开后，不直接进入扫描，而是先让用户选模式：

- SKU 上架
- 容器上架

这是一个很重要的 Web 交互决策：

- 不把两套流程混在一个面板里
- 先定模式，再定工作对象

对 PDA 也很有参考价值。

## 3. SKU上架模式

## 3.1 当前主流程

1. 录或扫上架单号
2. 拉上架单任务
3. 扫 SKU
4. 扫货位
5. 选效期 / 批次
6. 录数量
7. 保存上架

## 3.2 焦点流

当前组件会自动引导：

- 没有上架单：聚焦上架单号
- 有上架单无 SKU：聚焦 SKU
- 有 SKU 无货位：聚焦货位
- 货位成功后：聚焦数量

这是一条非常标准的 PDA 可复用工作流。

## 3.3 上架单加载后的页面状态

加载上架单成功后，当前页会显示：

- 上架单卡片
- 上架进度
- 当前 SKU 相关任务
- 右侧上架记录

同时支持：

- 清空当前上架单

## 3.4 SKU扫码后的前端规则

扫码到 SKU 后，前端会：

- 查询 SKU 信息
- 在当前上架单任务里找匹配 SKU
- 如果该 SKU 的所有任务都已完成，直接 warning
- 否则把它设成当前任务对象

## 3.5 货位扫码后的前端规则

扫码货位后，前端会：

- 调 `/api/v1/shelving/location`
- 拿到库区质量信息
- 根据当前 SKU 在上架单里的任务质量类型做前端过滤

也就是说，前端已经提前做了：

- 质量区与任务匹配筛选

不是把所有错误都留到后端。

## 3.6 效期 / 批次选择

如果当前 SKU 对应多组任务：

- 不同效期
- 不同批次

当前 Web 会拆成两个选择器：

- 效期
- 批次

并且根据选择结果动态更新：

- `maxQuantity`
- 当前任务

这说明当前 Web 交互明确不允许“用户不区分任务来源就直接上架”。

## 3.7 数量输入规则

当前规则：

- 数量必须大于 0
- 不允许超过 `maxQuantity`
- 如果手工输入超出，会 toast warning 并截断到最大值

## 3.8 上架成功后的前端行为

成功后：

- 新增本地上架记录
- 刷新上架单进度
- 如果上架单已完成：
  - toast 完成
  - 清空上架单、SKU、货位、数量
- 如果未完成：
  - 清空当前 SKU、货位、数量
  - 要求重新扫描下一次

这里的核心风格是：

- 一次动作只完成一次任务
- 成功后强制回到下一轮扫描态

## 4. 容器上架模式

## 4.1 当前主流程

1. 扫容器
2. 扫 SKU
3. 扫货位
4. 录数量
5. 保存上架

## 4.2 焦点流

- 无容器：聚焦容器
- 有容器无 SKU：聚焦 SKU
- 有 SKU 无货位：聚焦货位

## 4.3 页面状态展示

当前容器模式会显式展示：

- 当前容器
- 容器内货品明细
- 当前货位
- 当前 SKU
- 最近上架记录

这说明当前 Web 很强调“当前上下文可见”。

## 4.4 当前容器模式的前端约束

- 没扫描容器前不能扫 SKU
- 没扫到 SKU 前不能扫货位
- 没有容器、货位、SKU、数量时不能保存

这是一条严格串行的流程。

## 4.5 保存后的前端行为

成功后：

- 新增一条上架记录
- 更新本地容器货品数量
- 如果容器还有货：
  - 保持容器上下文
  - 清空当前项
- 如果容器已空：
  - 清空整个容器上下文

这种交互特别适合 PDA，因为操作员天然是“一个箱一个箱处理”。

## 5. 当前 Web 上架页的交互风格总结

### 5.1 明确的顺序感

不允许用户乱跳步骤，必须按：

- 先载入工作对象
- 再识别执行对象
- 再识别目标货位
- 最后确认数量

### 5.2 记录即时可见

操作成功后，右侧记录区立刻可见，减少用户不确定感。

### 5.3 失败即时反馈

当前主要用：

- toast error
- toast warning

不会让用户自己去表格里找错误。

## 6. 给 PDA 的结论

后续 PDA 做上架时，最值得继承的是这三个点：

- 严格的扫描顺序
- 当前上下文始终可见
- 成功后自动回到下一步扫描准备态

Web 上的大卡片、双栏布局、批量记录区可以缩，但这些交互原则最好不要丢。

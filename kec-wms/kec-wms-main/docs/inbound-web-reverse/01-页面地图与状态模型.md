# 页面地图与状态模型

## 1. 页面入口

当前 Web 端入库相关页面主要有：

- `/asn-sign-in`
  - ASN 签收
- `/receiving`
  - 收货模式选择页
- `/receiving/sku`
  - SKU 收货页
- `/receiving/container`
  - 容器收货页
- `/putaway/create`
  - 创建上架单
- `/putaway`
  - 上架单管理
- `/shelving`
  - 上架执行

## 2. 页面关系

当前 Web 端入库 UI 关系可以理解成：

1. 先在 `/asn-sign-in` 完成签收
2. 再进 `/receiving` 选择收货模式
3. 在 `/receiving/sku` 或 `/receiving/container` 执行收货
4. 收货后进 `/putaway/create` 创建上架单
5. 在 `/putaway` 查看上架单
6. 最后在 `/shelving` 执行上架

## 3. 主要布局风格

### 3.1 收货页

`SkuReceivingPage` 和 `ContainerReceivingPage` 都是：

- 左侧操作面板
- 右侧明细与状态卡片

这类布局非常适合 PDA 复刻成：

- 单页工作台
- 顶部当前单据
- 中间当前任务
- 底部主操作区

### 3.2 上架页

`ShelvingPage` 也是类似结构：

- 左侧扫描/输入面板
- 右侧状态卡片和记录区

### 3.3 创建上架单页

`CreatePutawayPage` 是标签页型页面：

- SKU 收货来源
- 容器收货来源

更偏管理页面，不是纯扫描页面。

## 4. 当前 Web 端的状态中心

## 4.1 `receiving-store.ts`

收货相关状态集中在 `useReceivingStore`。

核心状态包括：

- `currentAsn`
- `asnLines`
- `receivingBusinessMode`
- `currentContainer`
- `containerItems`
- `currentItem`
- `availableBatchLines`
- `quantity`
- `qualityStatus`
- `batchNumber`
- `expiryDate`
- `serialNumbers`
- `isLoading`
- `isSubmitting`
- `showFirstReceivingDialog`

这个 store 的特点是：

- 以“当前 ASN”作为页面工作上下文
- 以“当前收货项”作为操作焦点
- 模式切换时会清空大量状态，避免残留上下文污染下一次操作

## 4.2 `shelving-store.ts`

上架相关状态集中在 `useShelvingStore`。

核心状态包括：

- `currentContainer`
- `containerItems`
- `currentLocation`
- `currentSku`
- `quantity`
- `maxQuantity`
- `serialNumbers`
- `availableSerialNumbers`
- `shelvingRecords`
- `isLoading`
- `isSubmitting`

它的特点是：

- 上架操作被拆成“容器 / SKU / 货位 / 数量”的逐步聚焦过程
- 每完成一次上架，当前任务状态会被清空，准备下一次扫描

## 5. 当前 Web 端的交互基调

当前页面整体是“工位式 UI”，不是表单式后台。

表现为：

- 先扫主单
- 再扫对象
- 再补少量必要输入
- 最后执行

配套交互习惯：

- 成功后自动 focus 到下一个输入框
- 失败后保留当前上下文，并把焦点打回关键输入框
- 当前任务信息会在面板里立即显性展示
- 关键动作尽量只保留 1 到 2 个主按钮

## 6. 给 PDA 的第一层结论

如果后续做 PDA，最值得保留的不是 Web 的布局，而是它的状态模型：

- 一个页面只服务一个当前工作对象
- 所有输入都围绕当前对象推进
- 一次成功操作后立刻回到下一次扫描准备态

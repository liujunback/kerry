# 上架单创建与管理UI交互

## 1. 创建上架单页：`/putaway/create`

对应组件：

- `create-putaway-page.tsx`

## 1.1 页面定位

这是一个偏“管理台”的页面，不是扫描工作台。

它的核心任务是：

- 从待上架来源中挑选数据
- 生成上架单

## 1.2 当前布局

采用 Tab 切换：

- SKU 收货来源
- 容器收货来源

每个 Tab 都有：

- 顶部筛选区
- 中间选择状态条
- 下方表格

## 1.3 SKU来源页

当前通过：

- `GET /api/v1/putaway/pending-lines`

拉待上架 ASN Line。

交互特点：

- 可筛选
- 可多选
- 顶部显示已选数量
- 只有选中后才能创建上架单

## 1.4 容器来源页

当前通过：

- `GET /api/v1/putaway/pending-containers`

拉待上架容器。

交互风格和 SKU 来源页一致，只是操作对象换成了容器。

## 1.5 创建按钮规则

当前 Web 明确要求：

- SKU Tab 下，至少选中一条
- 容器 Tab 下，至少选中一个容器

否则直接 toast 提示。

## 1.6 成功后的行为

创建成功后：

- 清空当前选择
- 刷新列表

这是典型的“管理页刷新式交互”，后续 PDA 不一定需要完全照搬。

## 2. 上架单管理页：`/putaway`

对应组件：

- `putaway-management-page.tsx`

## 2.1 页面定位

这是上架单查询、查看、打印页面，不是执行页。

## 2.2 页面能力

- 筛选上架单
- 查看详情
- 单张打印
- 批量打印

## 2.3 交互风格

- 表格为主
- 行内快捷操作
- 支持批量选择
- 详情通过弹窗打开

## 2.4 明细管理特点

表格展示的重点字段包括：

- 上架单号
- ASN 单号
- 状态
- 总量 / 已上架 / 待上架
- 客户
- 仓库
- 上架模式
- 创建时间

这说明当前 Web 管理端更关注：

- 单据状态
- 进度
- 可追溯性

## 3. 给 PDA 的结论

创建上架单和上架单管理这两页更像后台管理页面。

后续 PDA 开发时可以只借鉴它们的业务约束，不必照搬它们的结构：

- PDA 不一定需要大表格
- PDA 更适合“扫描单号 -> 拉任务 -> 执行”
- 但“来源类型分流”和“必须先选来源再生成任务”这两个业务规则仍然值得保留

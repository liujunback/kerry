# 给PDA的交互约束与复用建议

## 1. 目标

本文件不是在设计 PDA 界面，而是从当前 Web 端提炼出“后续 PDA 最值得继承的交互规则”。

## 2. 必须继承的交互原则

## 2.1 单页只服务一个当前工作对象

当前 Web 非常强调：

- 当前 ASN
- 当前容器
- 当前 SKU
- 当前货位

任何时刻都应该有一个明确的“当前对象”。

PDA 端应该保留这种单对象聚焦，而不是一屏放太多并行任务。

## 2.2 扫描优先，手输兜底

当前 Web 里的主路径始终是扫码。

手工录入只在这些场景出现：

- 数量输入
- 批次/效期补录
- 特殊码值手输

PDA 端也应保持这个优先级。

## 2.3 成功后自动推进

当前 Web 几乎每个核心操作都有这一特征：

- 成功后自动清空当前输入
- 自动聚焦下一输入点
- 自动回到下一轮工作态

这是非常典型的作业端设计，PDA 端建议保留。

## 2.4 错误后不要清空全部上下文

当前 Web 大多数错误不会把整个页面状态清空，只会：

- toast 报错
- 清空当前错误输入
- 焦点回到关键输入点

PDA 端也建议保持这种策略。

## 3. Web里值得直接复用的状态模型

## 3.1 收货页

建议复用这套状态抽象：

- 当前单据
- 当前作业模式
- 当前容器
- 当前收货项
- 当前数量
- 当前质量
- 当前批次/效期
- 当前序列号列表

## 3.2 上架页

建议复用这套状态抽象：

- 当前上架单
- 当前容器
- 当前 SKU
- 当前货位
- 当前数量
- 当前可用序列号
- 当前操作记录

## 4. 需要明确继承的边界规则

后续 PDA 做的时候，建议直接继承这些 Web 端边界：

- 没有主单据时，不允许进入后续扫描
- 没有容器时，不允许扫容器内 SKU
- 没有 SKU 时，不允许录数量和目标货位
- 数量不能超过前端已知最大值
- 批次管理 SKU 必须补批次
- 效期管理 SKU 必须补效期
- 序列号管理 SKU 必须补齐序列号
- 上架货位必须先过货位合法性校验

## 5. Web端风格里不一定要照搬的部分

PDA 不一定要原样复用这些东西：

- 双栏布局
- 大表格
- 批量勾选
- 管理型筛选器
- 复杂弹窗层级

这些更像 Web 管理端能力，不是手持端必须保留的交互形式。

## 6. PDA更适合怎么继承

更推荐把 Web 端逻辑翻译成下面这种手持端结构：

- 顶部：
  - 当前单据 / 当前容器 / 当前任务摘要
- 中部：
  - 当前主输入框
- 底部：
  - 当前动作按钮
- 次级页面或抽屉：
  - 序列号采集
  - 任务详情
  - 历史记录

## 7. 最值得保留的五条规则

如果只保留五条，我建议保留这五条：

1. 任何时刻都要有明确的当前工作对象。
2. 主路径必须是扫码，手输只是补位。
3. 成功后自动回到下一次扫描准备态。
4. 出错后只回退当前输入，不清空整页上下文。
5. 所有数量、质量、批次、效期、序列号约束，都要在前端先做一层快速阻断。

## 8. 本文件小结

当前 Web 端入库 UI 最有价值的，不是视觉，而是“作业节奏”：

- 先锁定上下文
- 再逐步推进
- 每次只完成一个明确动作
- 做完立即进入下一轮

这套节奏非常适合后续 PDA 继续沿用。

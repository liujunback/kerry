# 签收与收货UI交互

## 1. ASN签收页：`/asn-sign-in`

对应组件：

- `backend/src/components/asn-sign-in/sign-in-page.tsx`

## 1.1 页面结构

- 左侧 1/3：
  - ASN 输入框
- 右侧 2/3：
  - 已签收列表
  - 总数量统计

## 1.2 交互顺序

1. 页面加载后自动聚焦 ASN 输入框
2. 用户扫码或输入 ASN 单号
3. 前端先用 `/api/v1/asn?asnNumber=...` 精确查 ASN
4. 查到后调用 `/api/v1/asn/{id}/sign-in`
5. 成功后：
   - 把 ASN 插入右侧列表
   - toast 成功
   - 清空输入框
   - 重新聚焦输入框
6. 如果该 ASN 已在当前页面签收列表中：
   - 不重复提交
   - 直接 warning toast

## 1.3 当前风格特点

- 强调连续扫码
- 页面不要求用户跳转详情
- 成功结果留在本页，方便现场确认

## 1.4 PDA可复用点

- 扫码即提交
- 成功留痕列表
- 自动回焦

## 2. 收货模式选择页：`/receiving`

对应组件：

- `backend/src/components/receiving/receiving-landing-page.tsx`

## 2.1 页面作用

它不是业务执行页，而是模式分流页。

当前只做两件事：

- 去 SKU 收货
- 去容器收货

如果 URL 上带 `asn` 参数，会把这个 ASN 透传给后续页面。

## 2.2 交互风格

- 卡片式选择
- 无复杂逻辑
- 只是入口，不保存状态

## 3. SKU收货页：`/receiving/sku`

对应组件：

- `sku-receiving-page.tsx`
- `sku-scan-panel.tsx`
- `receiving-store.ts`

## 3.1 页面主流程

1. 扫 ASN
2. 扫 SKU
3. 录数量
4. 选质量状态
5. 补批次/效期
6. 必要时录序列号
7. 保存收货

## 3.2 焦点流

当前组件会主动做焦点控制：

- 没有 ASN 时，聚焦 ASN 输入框
- 有 ASN 后，聚焦 SKU 输入框
- 手动录入模式下，扫完 SKU 会跳到数量输入框
- 扫描模式下，扫完 SKU 保持在 SKU 输入框，便于连续扫

这是当前 Web 页非常核心的节奏设计。

## 3.3 两种收货节奏

### 手动录入模式

- 适合一行商品一次性录较大数量
- 扫 SKU 后手动填数量
- 支持 `+/-` 和快捷数量按钮

### 逐件扫描模式

- 适合逐件扫码
- 如果连续扫到同一 SKU，数量自动 `+1`
- 达到最大可收数时直接 warning

这个模式对 PDA 特别有参考价值。

## 3.4 当前任务区怎么变化

扫到有效 SKU 后，页面会把“当前收货项”置为：

- `asnLineId`
- `sku`
- `maxQty`

同时：

- 如果有多个可选批次，前端会展示批次选择
- 如果 ASN 行自带批次/效期，会先自动带入

## 3.5 数量输入边界

当前前端会限制：

- 数量不能小于 0
- 数量不能超过 `maxQty`

这里的限制不仅靠后端，store 里也做了前端约束。

## 3.6 质量状态交互

当前只暴露两个质量按钮：

- `GOOD`
- `DAMAGED`

交互特点：

- 当前项未选定前不可用
- 用大按钮切换，不用下拉
- 适合触屏场景

## 3.7 批次、效期、序列号

### 批次

- 批次管理 SKU 才显示
- 如果有多个可选批次，显示下拉
- 如果只有一个或无批次，显示只读文本

### 效期

- 效期管理 SKU 才显示
- 采用日期输入

### 序列号

- 序列号管理 SKU 才显示提示块
- 数量不匹配时，点保存不会直接失败，而是弹序列号采集流程

这个设计非常适合 PDA：

- 先确定业务动作
- 再进入专用序列号采集弹窗

## 3.8 保存与继续

当前主操作是：

- `确认收货`
- `继续收货`

其中：

- `确认收货`
  - 只有当前项存在且数量大于 0 才可点
- `继续收货`
  - 不是直接提交业务
  - 是确认后清空当前项，回到继续扫 SKU 的准备态

## 3.9 收货成功后的前端行为

保存成功后：

- 更新本地 ASN 行状态
- 更新 ASN 总收货数量
- 如果 ASN 已收完：
  - toast 成功
  - 清空当前 ASN
  - 页面回到初始态
- 如果 ASN 未收完：
  - toast 成功
  - 仅清空当前项

## 3.10 首收弹窗

如果 SKU 是首次收货，前端会弹：

- `FirstReceivingDialog`

它不是收货主流程本身，但属于 Web 当前补充交互的一部分。

## 4. 容器收货页：`/receiving/container`

对应组件：

- `container-receiving-page.tsx`
- `container-scan-panel.tsx`

## 4.1 页面主流程

1. 扫 ASN
2. 扫容器
3. 扫 SKU
4. 录数量 / 连扫加数
5. 选质量
6. 必要时录序列号
7. 保存到容器
8. 关箱或重装箱

## 4.2 焦点流

当前焦点顺序非常清晰：

- 无 ASN：焦点在 ASN
- 有 ASN 无容器：焦点在容器
- 有容器后：焦点在 SKU

这非常适合 PDA 做成连续扫描工作流。

## 4.3 容器状态展示

扫描容器成功后，当前 Web 会显示：

- 容器编码
- 容器类型
- 容器内 SKU 汇总
- 按 SKU 分组后的装箱明细

这是典型的“边收边看箱内内容”模式。

## 4.4 关箱与重装箱

当前 Web 端有两个很重要的容器动作：

- `关箱`
- `重新装箱`

并且：

- 关箱前如果当前项还有未保存数量，会先尝试保存
- 关箱成功后，如果 ASN 已完结，会清空 ASN
- 否则只清空容器，准备下一箱

## 4.5 容器收货的交互风格

- 容器是一级工作对象
- SKU 是容器上下文内的二级对象
- 当前页会明显区分“当前箱”“箱内已装内容”“当前待收项”

## 5. 给 PDA 的收货结论

当前 Web 收货最值得复用的不是布局，而是这几个交互原则：

- 先锁定当前单据，再锁定当前容器/当前项
- 扫描优先，手输兜底
- 成功后自动回到下一次扫描状态
- 当前上下文必须始终可见
- 对序列号和首收这类复杂输入，使用二级弹层，不挤进主操作面板

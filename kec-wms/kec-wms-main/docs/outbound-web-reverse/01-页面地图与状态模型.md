# 页面地图与状态模型

## 1. 页面入口

当前 Web 端出库相关页面主要有：

- `/orders`
  - 出库订单列表
- `/orders/[id]`
  - 订单详情
- `/pick-orders`
  - 拣货单列表
- `/pick-orders/create`
  - 创建拣货单
- `/pick-orders/[id]`
  - 拣货单详情
- `/packing`
  - 打包执行页
- `/checkout`
  - 签出执行页
- `/manifest-orders`
  - 集运单管理页
- `/manifest-mount`
  - 集运挂载执行页

## 2. 页面关系

当前 Web 端出库 UI 可以理解成：

1. 先在 `/orders` 创建和管理订单
2. 在 `/orders` 做库存分配、回退
3. 在 `/pick-orders/create` 生成拣货单
4. 在 `/pick-orders` 管理或打印拣货单
5. 在 `/packing` 执行打包
6. 在 `/checkout` 执行签出
7. 在 `/manifest-orders` 创建集运单
8. 在 `/manifest-mount` 执行挂载和集运完结

## 3. 主要布局风格

### 3.1 列表管理页

`/orders`、`/pick-orders`、`/manifest-orders` 这类页面主要是：

- 顶部筛选区
- 中部数据表格
- 行内快捷操作
- 支持批量勾选

这类页面更偏后台管理台，不是现场作业台。

### 3.2 执行页

`/packing`、`/checkout`、`/manifest-mount` 都是典型工作台布局：

- 左侧 1/3：输入、扫描、主按钮
- 右侧 2/3：状态卡片、统计卡片、明细或记录表

这说明当前 Web 执行页已经在向“手持端作业方式”靠近。

## 4. 当前 Web 端的状态中心

## 4.1 订单与拣货单列表页

这两类页面的状态比较轻，主要是：

- 列表数据
- 分页、排序、筛选
- 行选择状态
- 批量动作的加载态

查询条件大多跟随 URL 参数。

## 4.2 打包页

打包页状态集中在：

- `backend/src/components/packing/packing-page.tsx`
- `backend/src/stores/packing-store.ts`

核心状态包括：

- `scanType`
- `moduleState`
- `currentPickOrder`
- `pickOrderLines`
- `selectedOrder`
- `packagingMaterials`
- `materialOptions`
- `currentItem`
- `serialNumbers`
- `shouldFocusSku`
- `shouldFocusMaterial`
- `shouldFocusTaskNumber`

特点是：

- 有明显“当前上下文”
- 有明显“当前步骤”
- 成功后会推进到下一焦点
- 关键节点会再向服务端刷新做纠偏

## 4.3 签出页

签出页状态集中在 `backend/src/components/checkout/checkout-page.tsx`。

核心状态包括：

- `selectedWarehouseId`
- `checkoutType`
- `containerInput`
- `scanInput`
- `currentContainerId`
- `containerNumber`
- `channelName`
- `orderCount`
- `parcelCount`
- `records`
- `isLoading`
- `isSubmitting`

特点是：

- 先锁容器，再连续扫码
- 当前容器就是整页工作上下文

## 4.4 集运挂载页

集运挂载页状态集中在 `backend/src/app/(dashboard)/manifest-mount/page.tsx`。

核心状态包括：

- `manifestInput`
- `currentManifestId`
- `manifestNumber`
- `manifestChannelName`
- `manifestWarehouseName`
- `manifestStatus`
- `checkoutInput`
- `containerCount`
- `orderCount`
- `parcelCount`
- `records`
- `isLoading`
- `isSubmitting`

特点是：

- 先锁集运单，再连续扫签出单
- 当前集运单就是整页工作上下文

## 5. 当前 Web 端的交互基调

当前页面整体是“工作台式 UI”，不是普通后台表单页。

表现为：

- 先锁定当前单据
- 再围绕当前单据做连续输入
- 成功后自动聚焦到下一输入点
- 错误后保留上层上下文，只回退当前输入
- 执行页尽量只保留 1 到 2 个主动作

## 6. 给后续终端的第一层结论

如果后续要做其他终端，最值得继承的不是当前 Web 的具体布局，而是它的状态模型：

- 一页只服务一个当前工作对象
- 所有输入都围绕当前对象推进
- 一次成功操作后立即回到下一轮扫描准备态

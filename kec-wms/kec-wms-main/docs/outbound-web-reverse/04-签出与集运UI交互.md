# 签出与集运UI交互

## 1. 签出页：`/checkout`

对应组件：

- `backend/src/components/checkout/checkout-page.tsx`

## 1.1 页面定位

这是典型的连续扫码工作台。

核心任务是：

- 先锁定板号/袋号
- 再连续扫订单号或运单号
- 最后完结当前板/袋

## 1.2 页面结构

- 左侧 1/3：
  - 仓库选择
  - 签出类型
  - 板号/袋号输入
  - 扫描输入
  - 完结按钮
- 右侧 2/3：
  - 渠道、订单数、包裹数统计卡
  - 扫描记录表

## 1.3 交互顺序

1. 页面加载后聚焦板号/袋号输入
2. 用户先选仓库
3. 选择 `PALLET/BAG`
4. 输入板号/袋号并确认
5. 成功后进入连续扫码状态
6. 持续扫描订单号或运单号
7. 点击“完结本板/本袋”
8. 成功后页面整体重置

## 1.4 焦点流

- 页面初始：
  - 聚焦板号/袋号输入
- 容器校验成功：
  - 聚焦扫码输入
- 扫码成功后：
  - 继续聚焦扫码输入
- 扫码失败后：
  - 继续聚焦扫码输入
- 完结成功后：
  - 回到容器输入

## 1.5 按钮启用条件

### 完结按钮

- 只有存在扫描记录时才可点
- 提交中不可点

### 仓库选择

- 当前容器锁定后禁用

## 1.6 报错反馈

- 未选仓库：toast
- 未先扫板号/袋号：toast
- 扫码失败：toast
- 完结失败：toast

## 1.7 当前风格特点

- 容器就是当前工作上下文
- 同一页上持续完成整板/整袋任务
- 成功后不跳页，继续准备下一次扫描

## 2. 集运挂载页：`/manifest-mount`

对应页面：

- `backend/src/app/(dashboard)/manifest-mount/page.tsx`

## 2.1 页面定位

这是签出后的下一层工作台。

核心任务是：

- 先锁定集运单
- 再连续扫描签出单
- 最后完结集运

## 2.2 页面结构

- 左侧 1/3：
  - 集运单输入
  - 集运单摘要
  - 签出单输入
  - 集运完成按钮
- 右侧 2/3：
  - 渠道、容器数、订单数、包裹数统计卡
  - 挂载记录表

## 2.3 交互顺序

1. 页面初始聚焦集运单输入
2. 用户扫描集运单
3. 校验成功后显示集运单摘要
4. 焦点切到签出单输入
5. 持续扫描签出单号
6. 挂载记录和统计实时更新
7. 点击“集运完成”
8. 成功后页面整体重置

## 2.4 焦点流

- 页面初始：
  - 聚焦集运单输入
- 集运单校验成功：
  - 聚焦签出单输入
- 挂载成功：
  - 继续聚焦签出单输入
- 挂载失败：
  - 继续聚焦签出单输入
- 集运完成：
  - 回到集运单输入

## 2.5 按钮启用条件

### 集运完成按钮

- 只有当前已锁定集运单
- 且至少存在 1 条挂载记录
- 且非提交中

## 2.6 报错反馈

- 集运单为空或校验失败：toast
- 未先锁定集运单就扫签出单：toast
- 挂载失败：toast
- 集运完成失败：toast

## 2.7 当前风格特点

- 与签出页结构高度一致
- 说明当前 Web 端已经形成统一的“连续扫码执行页”模式

## 3. 签出与集运这类页面的共同结论

当前 Web 端在这两类页面中都强烈体现出：

- 先锁定一个主工作对象
- 再围绕这个对象做连续扫描
- 成功后自动回到下一轮扫描准备态
- 失败时只回退当前输入，不丢失上层上下文

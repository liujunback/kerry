# 打包UI交互

## 1. 打包页：`/packing`

对应组件：

- `backend/src/components/packing/packing-page.tsx`
- `backend/src/components/packing/pick-order-packing-scan-panel.tsx`
- `backend/src/components/packing/order-packing-scan-panel.tsx`
- `backend/src/components/packing/modules/pick-order-module.tsx`
- `backend/src/components/packing/modules/order-module.tsx`
- `backend/src/stores/packing-store.ts`

## 1.1 页面定位

这是当前 Web 端最接近现场作业台的页面。  
它不是普通表单页，而是扫描驱动页面。

## 1.2 当前主流程

1. 扫描拣货单号、订单号、容器号或格口号
2. 前端调用 `packing/lookup` 识别当前模式
3. 自动进入当前单据上下文
4. 如未开始打包，则自动调用开始打包接口
5. 持续扫描 SKU
6. 订单打满后切到包材
7. 扫包材
8. 扫 `GB/CLOSEBOX/CLOSE/关箱` 或点击关箱

## 1.3 当前模式分流

当前打包页不是只有一种模式，而是四种入口共用一页：

- `PICK_ORDER`
- `ORDER`
- `CONTAINER`
- `CELL`

这说明当前 Web 已经把“识别扫描对象类型”放在前端主流程里了。

## 2. 拣货单模式

## 2.1 左侧操作面板

- 输入拣货单号
- 输入 SKU
- 输入包材
- 下拉选择包材
- 关箱按钮

## 2.2 右侧状态与明细

- 顶部拣货单卡片
- 下方聚合后的 SKU+货位+批次明细表

## 2.3 焦点流

- 刚加载拣货单成功：
  - 焦点去 SKU
- SKU 扫描成功且订单未完成：
  - 继续停留在 SKU
- 当前订单打满：
  - 焦点切到包材输入
- 关箱成功：
  - 若整张拣货单未完成，回到 SKU
  - 若整张拣货单完成，回到任务号输入

## 2.4 按钮启用条件

### 任务加载按钮

- 任务号非空
- 当前还没有加载拣货单

### 关箱按钮

- 存在 `pendingCloseOrder`
- 已经选择至少 1 个包材
- 非提交中

## 2.5 特殊规则

- 如果当前存在待关箱订单，不允许继续扫 SKU
- 包材输入框支持扫描“关箱码”

## 3. 订单模式

## 3.1 当前交互特点

- 以单订单为中心
- 输入订单号后锁定当前订单
- 右侧显示的是当前订单行明细，而不是整张拣货单聚合表

## 3.2 焦点流

- 订单加载成功：
  - 焦点去 SKU
- 当前订单打满：
  - 焦点切到包材
- 关箱成功：
  - 清空订单号输入
  - 焦点回到订单号

## 3.3 按钮启用条件

- 当前订单未加载前，不能进入 SKU 扫描
- 关箱按钮仍然要求：
  - 有待关箱订单
  - 已选包材

## 4. 序列号弹窗

对应组件：

- `backend/src/components/packing/serial-number-scan-dialog.tsx`

## 4.1 触发时机

- 扫描到序列号商品，且后端返回“需要扫描 N 个序列号”

## 4.2 当前交互顺序

1. 打开弹窗
2. 自动清空旧数据
3. 自动聚焦输入框
4. 扫一个序列号，加入一个
5. 达到要求数量后自动提交
6. 或点击确认手动提交

## 4.3 当前前端规则

- 不允许重复序列号
- 不允许超过需要数量
- 数量不够时确认按钮不可正确完成

## 4.4 当前反馈方式

- 这里用的是 `alert`，不是 `toast`
- 这是打包页当前 UI 风格里比较例外的一块

## 5. 当前状态管理

打包页是当前 Web 端出库 UI 中状态最重的一页。

核心状态包括：

- `scanType`
- `moduleState`
- `currentPickOrder`
- `pickOrderLines`
- `selectedOrder`
- `packagingMaterials`
- `materialOptions`
- `serialNumbers`
- `shouldFocusSku`
- `shouldFocusMaterial`
- `shouldFocusTaskNumber`

它的关键特点是：

- 本地 store 驱动交互节奏
- 关键节点再调用服务端做纠偏刷新

## 6. 当前报错反馈风格

- 加载失败：toast
- SKU 扫描失败：toast
- 包材不存在：toast
- 未完成关箱前继续扫 SKU：toast
- 序列号采集局部异常：alert

## 7. 当前 Web 打包页的核心结论

当前 Web 打包页最值得复用的不是视觉，而是这套节奏：

- 先锁定当前工作对象
- 再围绕当前工作对象连续扫描
- 一旦出现“待关箱”状态，强制先完成关箱
- 成功后自动把焦点送到下一输入点

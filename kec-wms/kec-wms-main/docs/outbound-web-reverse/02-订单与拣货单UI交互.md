# 订单与拣货单UI交互

## 1. 订单列表页：`/orders`

对应组件：

- `backend/src/app/(dashboard)/orders/page.tsx`

## 1.1 页面定位

这是一个偏“管理台”的页面，不是现场执行页。

它的核心任务是：

- 查订单
- 批量分配
- 批量回退

## 1.2 当前布局

- 顶部筛选区
- 中间订单表格
- 行内操作菜单
- 回退原因弹窗

## 1.3 交互顺序

1. 页面加载后按 URL 参数查询订单
2. 用户筛选、分页、排序
3. 勾选订单
4. 点击批量分配或批量回退
5. 成功后刷新列表并清空勾选

## 1.4 按钮启用条件

### 批量分配

- 至少选中 1 条可分配订单
- 可分配状态为：
  - `CREATED`
  - `PENDING`

### 批量回退

- 至少选中 1 条可回退订单
- 可回退状态为：
  - `ALLOCATED`
  - `OUT_OF_STOCK`
- 必须填写回退原因

## 1.5 报错反馈

- 无有效选中项：直接 `toast.error`
- 接口失败：直接 `toast.error(data.message || 默认文案)`

## 1.6 当前风格特点

- 这是典型表格管理页
- 信息密度高
- 更适合作为后台页面，不适合直接迁移成现场执行页

## 2. 拣货单创建页：`/pick-orders/create`

对应页面：

- `backend/src/app/(dashboard)/pick-orders/create/page.tsx`

## 2.1 页面定位

这是“从已分配订单中挑选订单并生成拣货单”的页面。

## 2.2 当前交互风格

- 本质仍然是管理页
- 通过筛选 + 勾选 + 创建完成动作
- 不是扫码页

## 2.3 当前规则特点

- 先选仓库
- 再查可用订单
- 再选择订单生成拣货单

后续做其他终端时，更适合把它改造成：

- 扫单号进入
- 自动拉取候选订单

而不是复刻整页筛选表格

## 3. 拣货单列表页：`/pick-orders`

对应组件：

- `backend/src/app/(dashboard)/pick-orders/page.tsx`

## 3.1 页面定位

这是拣货单查询、取消、打印页，不是拣货执行页。

## 3.2 当前布局

- 顶部筛选区
- 中间拣货单表格
- 行内操作
- 支持多选和批量打印

## 3.3 交互顺序

1. 页面加载并查询拣货单
2. 用户筛选条件
3. 勾选拣货单
4. 点击批量打印
5. 或进入详情页查看、单条取消

## 3.4 按钮启用条件

### 批量打印

- 至少选中 1 条非取消状态任务

### 取消

- 前端可点击
- 最终是否可取消由后端状态判断

## 3.5 报错反馈

- 未选任务：toast
- 打印失败：toast
- 取消失败：toast

## 3.6 当前风格特点

- 高密度列表
- 更偏“任务管理”和“排班视角”
- 不适合后续终端直接照搬

## 4. 订单与拣货单这类页面的共同结论

当前 Web 里，订单和拣货单相关页面更像：

- 管理台
- 调度台
- 查询台

而不是：

- 手持作业页

所以后续如果要做其他终端，这些页面最值得继承的不是布局，而是：

- 哪些状态可操作
- 哪些动作需要前置条件
- 成功后刷新列表
- 失败时直接 toast

# 预报签收与快递退件建单

## 1. 预报退件创建

`POST /api/v1/returns` 当前是外部 API（接口）入口，需要 API key（接口密钥）并要求 `return:create`（退件创建）scope（权限范围）。

创建逻辑：

1. 校验客户和仓库。
2. 校验同仓库物流单号不能存在未完成退件单。
3. 校验 SKU（商品）存在且属于客户。
4. 生成退件单号。
5. 创建 `return_order`，类型固定为 `BUYER_RETURN`。
6. 创建 `return_order_line`，状态为 `PENDING_SIGN`。
7. 刷新退件单汇总。

预报退件创建只创建待签收数据，不做签收和清点。

## 2. 签收查找

`POST /api/v1/returns/sign-in/lookup` 按物流单号查找：

1. 优先找 `PENDING_SIGN`（待签收）的预报退件单。
2. 找到则返回 `PRE_RETURN`。
3. 找不到预报退件时，按物流单号匹配原出库订单。
4. 找到原出库订单则返回 `OUTBOUND_ORDER`。
5. 都找不到返回 `NOT_FOUND`。

这个优先级符合“预报退件优先于快递退件自动创建”。

## 3. 预报退件签收

`POST /api/v1/returns/sign-in/confirm` 如果传 `returnOrderId`：

1. 查找当前仓库下 `PENDING_SIGN`（待签收）的退件单。
2. 把所有明细状态更新为 `SIGNED`。
3. 把主单状态更新为 `SIGNED`。
4. 写入 `signTime` 和 `signedBy`。
5. 刷新主单汇总并返回签收结果。

## 4. 快递退件自动创建

如果签收确认没有 `returnOrderId`，但传入 `outboundOrderId`：

1. 校验同仓库物流单号没有未完成退件单。
2. 查找原出库订单和订单行。
3. 创建 `return_order`，类型为 `COURIER_RETURN`，状态直接为 `SIGNED`。
4. 把原出库订单行转成退件明细，状态为 `SIGNED`。
5. 记录原出库订单号和平台订单号。
6. 刷新主单汇总并返回签收结果。

## 5. 当前边界

- 快递退件必须能匹配原出库订单。
- 预报退件创建入口当前是外部 API（接口）风格，不是普通 Web（网页）表单创建。
- 签收阶段不写库存，库存只在退件上架阶段通过 `putaway`（上架入库操作）写入。

# 退件上架与库存落账

## 1. 上架候选

`GET /api/v1/returns/putaway/candidates` 查询可生成上架单的处理方式。当前只包含：

- 状态为 `DISPOSITION_RECEIVED`
- 动作为 `GOOD_PUTAWAY` 或 `DAMAGED_PUTAWAY`

`DESTROY` 当前不会进入退件上架候选。

## 2. 生成退件上架单

`POST /api/v1/returns/putaway/orders` 根据处理方式 ID（标识）生成退件上架单：

1. 查询所有处理方式，要求都属于当前仓库且状态为 `DISPOSITION_RECEIVED`。
2. 按退件单分组。
3. 每个退件单生成一个 `return_putaway_order`。
4. 每个处理方式生成一条 `return_putaway_line`。
5. 上架行复制 SKU（商品）、质量、批次、效期、容器、来源暂存库位等信息。
6. 处理方式和退件明细进入 `PENDING_PUTAWAY`。
7. 刷新退件单汇总。

## 3. 执行退件上架

`POST /api/v1/returns/putaway/execute` 执行上架：

1. 按退件上架单号查找 `PENDING` 或 `PARTIAL` 上架单。
2. 校验 SKU（商品）存在并属于客户。
3. 校验目标库位存在、启用、未锁定。
4. 良品只能上架到良品库区。
5. damaged（破损）不能上架到良品库区。
6. 按物流单号、容器号、SKU（商品）、质量匹配待上架行。
7. 校验上架数量不能超过剩余数量。
8. 在 SKU（商品）锁内开启事务，并对 `return_putaway_line` 做 `FOR UPDATE`（行级锁）。
9. 调用通用 `putaway`（上架入库操作）写库存。
10. 更新上架行、处理方式、退件明细、退件上架单和退件单汇总。
11. 创建 `return_putaway_detail` 执行记录。
12. 触发库存快照和 SKU（商品）汇总刷新。

## 4. 库存落账

退件上架通过 `inventory-operation-service.ts` 的 `putaway`（上架入库操作）写库存：

- `asnNumber` 使用退件单号 `returnNo`
- `referenceType` 使用 `RETURN_PUTAWAY`
- `referenceId` 使用退件单 ID（标识）
- `referenceNumber` 使用退件单号
- `referenceLineId` 使用退件明细 ID（标识）
- `qualityType` 按处理方式映射为 `GOOD` 或 `DAMAGED`
- `fifoDate` 使用签收时间，缺失时使用当前时间

因此退件上架最终会写入库存事件、库存桶，并刷新库存快照和 SKU（商品）汇总。

## 5. 当前风险边界

- 退件清点阶段只绑定暂存库位和容器，不形成可用库存。
- `DESTROY` 当前在处理方式阶段就可完成，不进入上架候选，也不会通过上架接口写库存。
- 退件上架执行支持部分上架，上架单状态会在 `PENDING`、`PARTIAL`、`COMPLETED` 间变化。
- 同一上架行并发执行靠 SKU（商品）锁和 `FOR UPDATE`（行级锁）保护。

# 退件总览与状态机

## 1. 覆盖范围

当前退件模块后端入口：

- `GET /api/v1/returns`
- `POST /api/v1/returns`
- `GET /api/v1/returns/[id]`
- `POST /api/v1/returns/sign-in/lookup`
- `POST /api/v1/returns/sign-in/confirm`
- `POST /api/v1/returns/counting/lookup`
- `POST /api/v1/returns/[id]/count-lines`
- `POST /api/v1/returns/[id]/complete-counting`
- `POST /api/v1/returns/[id]/dispositions`
- `POST /api/v1/returns/putaway/orders`
- `POST /api/v1/returns/putaway/execute`

## 2. 退件类型

当前代码定义两种退件：

- `BUYER_RETURN`：买家退件，先有预报退件单
- `COURIER_RETURN`：快递退件，签收时根据原出库订单自动创建

## 3. 状态

`ReturnStatus`（退件状态）当前定义：

- `PENDING_SIGN`：待签收
- `SIGNED`：已签收
- `COUNTING`：清点中
- `WAIT_DISPOSITION`：等待客户处理方式
- `DISPOSITION_RECEIVED`：已收到处理方式
- `PENDING_PUTAWAY`：待上架
- `PUTAWAYING`：上架中
- `COMPLETED`：完成

退件单主单状态不是单独手工维护，而是通过 `refreshReturnOrderRollup`（刷新退件单汇总）按明细状态汇总。

## 4. 主表

`ReturnOrder`（退件单）关键字段：

- `returnNo`：WMS（仓储系统）退件单号
- `returnType`：退件类型
- `preReturnNo`：预报退件单号
- `logisticsNo`：物流单号或包裹号
- `outboundOrderId/outboundOrderNo/platformOrderNo`：原出库订单信息
- `status`：退件主状态
- `signTime`、`countCompleteTime`、`strategyReceivedTime`、`completeTime`
- `totalExpectedQty`、`totalCountedQty`、`totalPutawayQty`、`totalLineCount`

同一租户、同一仓库、同一 `logisticsNo`（物流单号）只能有一个有效退件单。

## 5. 明细表

`ReturnOrderLine`（退件明细）承载清点结果：

- SKU（商品）、条码、预报数量、清点数量、已上架数量
- 质量：`GOOD` 或 `DAMAGED`
- 批次、效期
- 容器和退件暂存库位
- damaged（破损）照片 URL（统一资源定位符）列表
- 最新处理方式
- 明细状态

一个退件单可以包含多个明细，同一个 SKU（商品）可以因为质量、批次、效期不同拆成多条明细。

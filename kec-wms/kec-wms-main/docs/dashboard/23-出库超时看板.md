# 出库超时看板

## 一、功能概述

出库超时看板用于监控和追踪超过预计出库时间（expected_outbound_time）但尚未完成出库的订单，帮助运营团队及时发现和处理超时订单，提升出库效率和客户满意度。

## 二、页面布局

### 2.1 整体结构

页面采用**矩阵表格**布局，分为三个主要区域：

1. **筛选区**（顶部）：提供多维度筛选条件
2. **数据展示区**（中部）：矩阵表格展示超时订单分布
3. **操作区**（底部）：数据导出、刷新等功能

### 2.2 矩阵表格设计

**横向维度（列）**：预计出库日期 + 超时时长分段

```
| 状态 | 2026/01/30 |          | 2026/01/29 |          | ... | 汇总 |
|      | 9H  | -1D | -2D | -3D | -4D | -5D |     |      |
```

**纵向维度（行）**：订单状态

- 异常状态（红色高亮）
  - 匹配失败
  - 换号失败
  - 出库异常
- 正常流程状态
  - 待处理
  - 已分配
  - 待汇单
  - 汇单中
  - 已汇单
  - 拣货中
  - 已拣货
  - 分拣中
  - 分拣完成
  - 打包中
  - 已打包
  - 待发货
- 汇总行

**单元格显示格式**：`订单数 | 平均超时天数`

示例：`23 | 2.57` 表示该状态下有 23 个订单，平均超时 2.57 天

## 五、业务逻辑

### 5.1 超时判断条件

订单被判定为超时需同时满足以下条件：

```sql
WHERE NOW() > expected_outbound_time
  AND status NOT IN ('SHIPPED', 'CANCELLED')
```

说明：
- 当前时间已超过预计出库时间
- 订单状态不是"已发货"或"已取消"

### 5.2 超时时长计算

```sql
timeout_duration = NOW() - expected_outbound_time
```

### 5.3 时段分组逻辑

```sql
CASE
  WHEN timeout_duration <= INTERVAL '9 HOUR' THEN '9H'
  WHEN timeout_duration <= INTERVAL '1 DAY' THEN '-1D'
  WHEN timeout_duration <= INTERVAL '2 DAY' THEN '-2D'
  WHEN timeout_duration <= INTERVAL '3 DAY' THEN '-3D'
  WHEN timeout_duration <= INTERVAL '4 DAY' THEN '-4D'
  WHEN timeout_duration <= INTERVAL '5 DAY' THEN '-5D'
  ELSE '-5D+'
END AS timeout_bucket
```

### 5.4 订单状态映射

| 数据库状态 | 看板显示名称 | 状态类型 |
|-----------|------------|---------|
| MATCH_FAILED | 匹配失败 | 异常 |
| NUMBER_CHANGE_EXCEPTION | 换号失败 | 异常 |
| OUTBOUND_EXCEPTION | 出库异常 | 异常 |
| PENDING | 待处理 | 正常 |
| ALLOCATED | 已分配 | 正常 |
| PENDING_WAVE | 待汇单 | 正常 |
| IN_WAVE | 汇单中 | 正常 |
| WAVED | 已汇单 | 正常 |

## 七、数据查询

### 7.1 主查询 SQL

```sql
SELECT
  DATE(expected_outbound_time) AS expected_date,
  status,
  CASE
    WHEN EXTRACT(EPOCH FROM (NOW() - expected_outbound_time)) <= 9 * 3600 THEN '9H'
    WHEN EXTRACT(EPOCH FROM (NOW() - expected_outbound_time)) <= 24 * 3600 THEN '-1D'
    WHEN EXTRACT(EPOCH FROM (NOW() - expected_outbound_time)) <= 2 * 24 * 3600 THEN '-2D'
    WHEN EXTRACT(EPOCH FROM (NOW() - expected_outbound_time)) <= 3 * 24 * 3600 THEN '-3D'
    WHEN EXTRACT(EPOCH FROM (NOW() - expected_outbound_time)) <= 4 * 24 * 3600 THEN '-4D'
    WHEN EXTRACT(EPOCH FROM (NOW() - expected_outbound_time)) <= 5 * 24 * 3600 THEN '-5D'
    ELSE '-5D+'
  END AS timeout_bucket,
  COUNT(DISTINCT order_id) AS order_count,
  SUM(total_quantity) AS total_pieces,
  AVG(EXTRACT(EPOCH FROM (NOW() - expected_outbound_time)) / 86400) AS avg_timeout_days
FROM orders
WHERE NOW() > expected_outbound_time
  AND status NOT IN ('SHIPPED', 'CANCELLED')
  AND expected_outbound_time >= :start_date
  AND expected_outbound_time <= :end_date
  -- 其他筛选条件
GROUP BY expected_date, status, timeout_bucket
ORDER BY expected_date DESC,
  CASE status
    WHEN 'MATCH_FAILED' THEN 1
    WHEN 'NUMBER_CHANGE_EXCEPTION' THEN 2
    WHEN 'OUTBOUND_EXCEPTION' THEN 3
    WHEN 'PENDING' THEN 4
    WHEN 'ALLOCATED' THEN 5
    WHEN 'PENDING_WAVE' THEN 6
    WHEN 'IN_WAVE' THEN 7
    WHEN 'WAVED' THEN 8
    WHEN 'PICKING' THEN 9
    WHEN 'PICKED' THEN 10
    WHEN 'SORTING' THEN 11
    WHEN 'SORTED' THEN 12
    WHEN 'PACKING' THEN 13
    WHEN 'PACKED' THEN 14
    WHEN 'READY_SHIP' THEN 15
  END
```

### 7.2 明细查询 SQL

```sql
SELECT
  o.order_no,
  o.client_code,
  c.client_name,
  o.sku_count,
  o.total_quantity,
  o.expected_outbound_time,
  o.status,
  EXTRACT(EPOCH FROM (NOW() - o.expected_outbound_time)) / 3600 AS timeout_hours,
  EXTRACT(EPOCH FROM (NOW() - o.expected_outbound_time)) / 86400 AS timeout_days,
  o.created_at,
  o.allocated_at,
  o.picked_at,
  o.packed_at
FROM orders o
LEFT JOIN clients c ON o.client_id = c.id
WHERE NOW() > o.expected_outbound_time
  AND o.status NOT IN ('SHIPPED', 'CANCELLED')
  AND DATE(o.expected_outbound_time) = :expected_date
  AND o.status = :status
  AND timeout_bucket = :timeout_bucket
  -- 其他筛选条件
ORDER BY timeout_hours DESC
```

## 八、技术实现

### 8.1 数据库索引

为提升查询性能，需要创建以下索引：

```sql
-- 复合索引：超时查询核心索引
CREATE INDEX idx_orders_timeout
ON orders(expected_outbound_time, status)
WHERE status NOT IN ('SHIPPED', 'CANCELLED');

-- 单列索引：客户筛选
CREATE INDEX idx_orders_client ON orders(client_id);

-- 单列索引：日期范围查询
CREATE INDEX idx_orders_expected_date ON orders(expected_outbound_time);
```

### 8.2 性能优化

**缓存策略**
- 使用 Redis 缓存统计数据
- 缓存键格式：`timeout_dashboard:{filter_hash}`
- 缓存过期时间：5 分钟
- 缓存更新：订单状态变更时清除相关缓存

**查询优化**
- 限制查询时间范围（建议不超过 30 天）
- 使用物化视图存储预聚合数据
- 分页查询明细数据（每页 20 条）

**前端优化**
- 虚拟滚动：大数据量表格使用虚拟滚动
- 懒加载：明细数据按需加载
- 防抖：筛选条件变更后 500ms 再查询
